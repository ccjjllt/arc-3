# 010 — 前沿更新：从局部裁剪转向可按需取回的时序证据

检索日期：2026-10-13，Asia/Shanghai。已重新访问论文原文、作者项目页和作者仓库，未把旧 `frontier-findings.md` 当作新证据。本文只记录研究与候选设计；没有安装外部 harness、调用模型、启动 GPU、执行游戏或修改现有 solver。009 的正式 public LB 31.16 是本项目当前定位；以下公开开发集成绩不能与它直接排序。

## 决策

**008 是有依据的底层工具，但“当前帧裁剪更准确”作为下一轮奖牌研究目标过窄。** 新证据更支持问：当一个推理后来才需要某次旧动作的局部中间帧时，智能体能否准确取回、比较并更新机制假设？暂不转成全程强制世界模型、长摘要或多个代理；这些方案的计算成本和局部模型适配证据仍不足。

最可检验的候选是 **按真实 action/level/attempt 索引、按需读取较早动作完整动画的只读接口**。008 的区域读取可在内部复用，006 的自动追加摘要不叠加。这里是迁移假设，不是已实现或已验证收益。

## 五项一手证据及新核对

### 1. VISTA，2026-10-01：比旧网页更完整的观察消融

论文用 Opus 5 xhigh、GPT-5.6 Sol max，在 25 个公开游戏评估。Sol 的逐级消融为 notes 70.05 → 完整视觉记忆及主动 inspect 94.10 → 精确像素 99.00；加入 inspect 时也从自动多帧改为默认仅展示末帧，不能把差值全归给存储。三次完整运行为 99.00/98.90/99.23，另有 GLM-5.3 Flash 320B=66.93。关键限制：**每游戏上限 2,000 动作、48 小时**，并非 Kaggle 单 GPU 全集 9 小时。图像配置平均 30.7M tokens/game，不能与我们的 generated tokens 直接相除。原文没有证明 Qwen3.8-Flash-Next 的迁移增益。[论文 §4.3、A.2、B.1](https://arxiv.org/html/2610.02200v1)

旧项目页仍为 Sol 98.27、Opus 7,542 动作；论文为 Sol 99.00、Opus 7,302 动作。本文不拼接这两版数字。作者页承认公开游戏可能进入预训练；它描述从初见到完成的交互，但不提供隐藏集结果。[项目页](https://vista-research.github.io/)、[作者仓库](https://github.com/joshhhhhan/VISTA)

**对本项目的推论：** 值得借鉴的是“稍后主动重看原始证据”的访问方式。我们已有放大图像和像素 ASCII，不能把再加视觉输入当同样增量；也不能移植 48 小时条件下的每动作语言推理预算。

### 2. Tracing the Thoughts，2026-10-08：直接挑战“保留更多函数就会更好”

该研究观察 7 次不同模型/提示/运行模式，明确不是同条件重复或因果消融。25 公开游戏中，本地 Qwen3.8-27B-FP8 在 8 H100、每次计划动作 cap 50 的三次结果仅 8.39/6.78/6.84；不是我们的 Flash-Next。仅 33/630 次脚本引用跨关，74% 的边界前脚本被弃用。作者定位到旧关硬编码值的负迁移，个案修复是改为需重新传入的参数。论文未给可用于本项目的统一墙钟/生成 token 预算，且部分代码承诺随后公开。[论文 Table 1、§4](https://arxiv.org/html/2610.11450v1)

**对本项目的推论：** 007 确实保住函数，不等于函数对新状态仍适用。保留源代码、把当前观察作为参数、区分关卡事实与机制，是三个不同问题。不能以此论文的小 Qwen 负结果否定我们的强基线，也不能从 Opus 高分假定日志式工作流适配本地模型。

### 3. PRO-LONG：证据是可检索日志，而不是更多自写笔记

GPT-5.5、Opus 4.6、Fable 5 的默认比较为 25 public、500 动作/game、独立新 session；GPT 有五次重复。工具阶梯 23.1→27.2→38.3→41.2，支持程序查询价值；workspace 清空时 PRO-LONG 41.2→40.7，不能把收益归给持久笔记。94.6 pass@1 与 97.4 selective best@2 使用 Fable 5、2,000 动作，后者不是一次运行；相关费用为 $1,500/$1,750。没有同一墙钟下的本地 Qwen 对照。[论文 §2–3](https://arxiv.org/html/2607.20064v1)

目前仓库主入口已转为通用 coding CLI 记忆集成，ARC 实验在 `research/arc-agi-3`；不能下载当前主目录便认为复现了论文 agent。[作者仓库](https://github.com/alexisfox7/PRO-LONG)

**对本项目的推论：** Franzen 已能在 Python 中查询稳定历史帧，新增普通历史日志未必有增量。应先定位现有 accessible memory 缺了哪种原始观察，而非再默认插入摘要。

### 4. Tycho：可选建模优于自动反证后不断修模，且预算很大

Opus 4.8 四策略对照为 79.07/85.36/88.49/83.07；自动触发 builder 的预测匹配更高，却少过关、调用更多。每配置仅一次随机运行；25 public 中 5 游戏用于 harness 开发。调用上限 3,500/game、费用上限 $750/game，最佳 orchestrator 实际约 $5.78k/25 游戏、35.8M 输出 tokens。官方计分来自完整本地轨迹的确定性 competition replay，不能把 replay 本身当隐藏泛化；它也不同于只计最终解序列的 replay。后续换强模型的满分属于系统结果。[论文 Tables 1、2、6，§7](https://arxiv.org/html/2607.28287v1)、[作者实现](https://github.com/NIMI-research/Tycho)

**对本项目的推论：** 不照搬 builder 编排。其 orchestrator 输出量约是我们 005 analyzer 4.48M 的 8 倍；这只是生成量参照，不能转换成确定 GPU 倍数。优先让现有 actor 按需使用证据/局部程序，不因预测错误就新增强制 LLM 调用。[005 口径](../005/005-results-analysis.md)

### 5. TWIN：目标否证值得借鉴，全历史强制验证不适合直接搬

GPT-5.6 Sol 的 25 public 单次整局结果为 93.3、179/183 关；无 twin 的 coding agent 为 61.1、148 关，但 Twin 总 processed tokens 为其 2.4 倍，非等算力消融。累计 2.60B processed tokens、91.4 小时，其中逾 98% 为 cache reads；不是 91.4 个本地 GPU 小时，也不能据缓存比例忽略处理成本。其目标机制会排除已到达但未过关的候选，与“动力学拟合成功”分开。[论文 §Experimental Results、Appendix C/D](https://arxiv.org/html/2608.14490v1)

**对本项目的推论：** 003 没有触发真正目标否证，不足以否定这条路线；但本次不重新加 marker。应先让 actor 取得具体观察，在已有局部模型可信时再研究可自动绑定真实状态的目标候选证据。

## 额外协议检查：未纳入候选分数排名

- **Kepler** 原文明确：100 是开发后的最终 replay，并非官方 first-exposure 获取技能预算；同一 25 public 用于开发/评估，控制组曾从文件系统重建被移除 harness，因此没有有效独立消融。它只能作为观察通道与评估归因的提醒。[论文 §1、§3.1、§6.4](https://arxiv.org/html/2610.00834v1)
- **NVIDIA AVO** 官方文章报告 Opus 5、25 public、183 关、6,624 动作；使用文本观察、持久状态和监督，未在所读 ARC 专节披露可匹配的逐游戏计算预算/独立消融。不能把“同模型100”或 GPU kernel 实验的七天配置当 Kaggle 部署证据。[官方文章](https://developer.nvidia.com/blog/nvidia-avo-reaches-100-on-arc-agi-3-demonstrating-a-frontier-level-general-purpose-architecture-for-long-horizon-autonomous-agents/)

这些结果共同反对两种过度承诺：既不能说必须合成完整世界模型才能强，也不能说只加视觉记忆就能让离线 Qwen 接近满分。现有论文没有隔离本项目模型、量化、缓存、墙钟及 110 隐藏游戏条件。

## 本地代码核对：008 究竟缺少什么

这是本次新读源码得到的事实，不是论文推断：

1. [`_ascii_history_view_payload`](../../runtime-bundle/src/ARC3-Inference/inference/agent/tool_agent.py:2843) 遍历完整 `history_entries`，每条包含稳定帧、动作和 result。普通稳定历史已可访问。
2. [`_handle_animation`](../../runtime-bundle/src/ARC3-Inference/inference/agent/tool_agent.py:5766) 发送无动作索引的 `query=animation`；[solver](../../runtime-bundle/src/ARC3-Inference/inference/framework/solver.py:995) 返回当前 `self.animation_record`，该字段在后续动作处被覆盖。它不是可任意回查的完整动画库。
3. [006](../006/006-intervention-analysis.md) 增加的是较早动作的帧数/bbox 等元数据，真实送达/引用已验证；没有证明这足够恢复每帧的相对位移或对象身份。全文自动追加不是下一候选。
4. [008](../008/008-representation-analysis.md) 已解决指定矩形的字符/像素编码合同，却仍依赖选区，未解决长面板分槽、时序事实丢失或模型采用。继续扩大几何特判容易在公开病例上投入很多 CPU，却仍不回答隐藏覆盖。

因此，**008 应成为按需观察工具内部的可靠读数层**。优先评估能否为旧动作的完整中间帧提供稳定引用，再评估 actor 是否借此修正机制。不开发面向 tr87 的符号分类专家，也不同时引入跨关摘要、调度及多代理。

## 最可检验的迁移假设

**假设 H：** 在相同 Flash-Next 模型、9h 归一化墙钟和原调度下，给 actor 一个按真实旧 action 索引读取完整动画及指定区域的只读函数，会减少“stable frame 无变化⇒动作无信息”的误判，并在更多游戏上增加后续关卡覆盖。不新增强制反思/摘要模型调用；模型自主查询仍可能改变请求数和输入成本，必须实测。

### 最小候选

- 在实际 action 返回时保存该动作的原始动画链，键包含 game-session、level、attempt、action_num、frame_index；记录来自公开 observation，不从引擎读潜在状态。
- 按需返回有限个原始帧或局部像素；默认不把整条历史重新塞进 prompt。008 可作为内部区域读取器，但本轮不同时上线另一套 current-only 新工具。
- 存储采用紧凑数组/文件索引，避免每次 Python 调用重新序列化全部动画；明确 capture、可检索、被查询、被解释四层计数。记录 CPU/I/O、输出字符和模型输入成本。
- 不修改现有动作批次、no-op guard、函数保留、模型、调度和 deadline；006/007 仍关闭。工具说明应短且通用，不写游戏 ID、颜色语义或已知答案。

显式状态参数、跨关常量失效和目标候选更新分别保留为后续假设，不与 H 同时上线。只读 ROI 本身也不是全新能力：现有 `.ascii` 已能做稳定帧区域切片，H 的唯一信息增量是较早动作的完整中间帧可被选择，而非再提供一份稳定 history。若某失败已经有正确的稳定状态/转移 stdout，却在后续推理中记错，应归入证据归属或规则更新病例；不能把它归到缺动画或缺 mask。

### 先排除错误前提，再花 GPU

CPU 先确认两次以上真实动作后仍可按旧 action 精确取回每帧 hash；确认 RESET/跨关不会把旧动作错绑到当前帧。现有 005 中间帧未完整保存的地方只能独立重建观察病例，不能冒充恢复原运行。量化存储/读取成本，并先从现有轨迹标注“缺完整旧动画可能影响决策”和“已有足够证据但目标/规划失败”两类。

GPU 若获安排，先冻结一个 12 游戏池，包含多个动画病例、后关规划病例及易通控制，baseline 与 H 各一遍、相同游戏版本/顺序/3,482 秒预算、一次加载模型。预计沿用约 2.2h 会话的历史量级；实际以新配置/配额为准。池选择只用于机制筛选，不冒称未见留出，也不因某游戏正差再补选它。

### 可推翻 H 的观察与停止条件

1. **读取失败或错绑**：工程前提未成立，停止 GPU 扩跑；不能用分数评价尚未交付的机制。
2. **完整可用却几乎不被查询**：当前接口在预算内不可用，先改接口；与 003 一样，不能称已经否定信息本身的价值。
3. **查询后仍不能取得动作间的相对变化，或主要反复读取已有信息**：H 的“更多原始证据能改变机制学习”链条没有支持；不追加更长摘要解释失败。
4. **有明确纠正链但同池覆盖下降、改善只在一个已知游戏、或 prefill/I/O 挤占其他游戏机会**：当前版本不晋升。保留全池负结果，不删除回退游戏。
5. 只有跨多个机制病例出现正确采用、覆盖净收益且控制游戏无明显资源性回退，才值得交换 A/B 顺序再做一次独立会话。两次仍不能估计稳定的隐藏收益；之后用全25及正式提交检验迁移。

当前剩余 7.52h 是主任务提供的配额快照，不在本笔记中把它自动分配完。候选的第一次筛选和一次确认总量约 4.4h，已占可用资源的大半；没有采用证据时不启动第二轮。更强且可复现的公开竞赛基线若被主任务找到，应与本机制候选比较机会成本，不能因008已写代码就持续押注它。
