# 002 — 目标与机制发现、跨关卡学习、算力分配

日期：2026-10-10（Asia/Shanghai）  
对应结果：[002-strategy-improvement](../progress/002-strategy-improvement.md)  
前序：[001](001-baseline.md)；下一轮：[003](003-next-experiment.md)。

## 研究决策

主线选择 **强开源模型 + 可证伪的目标/机制假设 + 按需局部规划**，优先跨越首个未解关并扩大后段关卡覆盖；证据复用和收益导向的计算分配为支撑。具体从 dfranzen v3 继承成熟推理栈，先复现，再按失败轨迹决定修改。我们当前没有实测证明以下任何新机制能涨分。

优先研究顺序：

| 优先级 | 研究主题 | 原因 | 不满足时转向 |
|---|---|---|---|
| P0 | 完整基线与轨迹归因 | 没有它无法判断新增机制解决什么错误 | 优先解决真实运行问题 |
| P1a | 可证伪的目标假设与机制发现（方向 B） | 真实轨迹存在转移预测正确却目标错误，以及动画证据被忽略 | 若没有命中该失败类型，按轨迹重新排序 |
| P1b | 裁剪后证据检索、跨关卡复用（方向 A） | 后续关卡权重大；需定位重复推理是否因遗忘 | 若不是遗忘/重复探索主因，保持原版记忆 |
| P2 | 预计得分增量/时间的游戏调度 | 9 小时下无法对每个游戏无限推理 | 收益小或缓存损失大则保留原版 |
| P3 | 轨迹蒸馏/小规模适配 | 长期有价值，但剩余周期和轨迹质量受限 | 无独立增益就不启动训练 |

不优先投入：从零 RL、只记游戏 ID 的专家、全量生成游戏引擎、无差别反思/验证调用、纯粹堆更多提示词、多套大型 serving 栈重写。它们与当前证据和剩余时间不匹配。

**原始轨迹给出的新证据**：dfranzen v3 的 100 条公开 demo 轨迹均分 46.4930，固定已完成关卡集合的上限均值 49.1227。sk48 的一条轨迹中，模型自建转移函数预测了 16 步路径，真实转移匹配，但猜测的目标未触发通关；lf52 的失败轨迹漏用了暂态动画信息；tn36 的成功轨迹显式读取动画。详见原始日志与 [Notebook 分析](../../research/notebook-findings.md)。这支持优先研究目标/机制发现，不能从个案得出改进已奏效。动作效率改善仍可能间接帮助过新关。

核心反证要求：**不能把恢复旧式长摘要当成创新。** 新机制必须在固定底座上，说明它保留了什么会被原版丢掉的信息，以及付出的时间、上下文和缓存成本。

## 2. 方向 A：带证据的记忆与技能迁移

### 假设

长轨迹被裁剪或跨关卡后，模型可能重新探索已证实规则，或复用带旧布局常量的函数。轻量、事件触发的证据记录与参数化函数，可能减少真实动作和重复 tokens，而不会像全量摘要那样丢弃推理。

### 设计

保留原版推理历史；记录少量关键事件而非每轮写摘要：

```text
RuleEvidence:
  claim: 本游戏某种可操作、可反驳的局部规则
  evidence: [transition_id, ...]
  status: hypothesis | supported | contradicted
  scope: game / level / object-type
  exceptions: 可观察到的反例

Skill:
  source: 模型此前写出的 Python 函数
  inputs: 当前棋盘与参数，不把旧布局/坐标当永久常量
  preconditions: 适用的可观察对象与控制条件
  solved_level_evidence: 曾在哪个真实关卡生效
```

只在“过关、发现反例、原版上下文即将裁剪”时更新。先用确定性的日志索引保存事件，必要时把极短引用插入下一条用户消息，避免每个动作重写 system prefix 导致缓存失效。不要用置信度数值伪装未经校准的概率。

继承上一关规则作为假设；新布局、新物体或反例出现时更新适用范围。跨不同游戏只复用通用工具，不把一个游戏的具体规则当另一个游戏的真理。

### 代码位置与最小改动

基线 `ARC3-Inference/inference/agent/tool_agent.py`：上下文裁剪、关卡切换、函数保留与动作结果处理处。先新增小模块 `evidence_memory.py` 管理事件；提示改动集中在 `prompts.py`。这些是**拟实现路径**，本轮尚未创建。

### 手动实验

原版 A0；A1 仅新增上下文裁剪后仍可查询的关键证据索引；A2 再加入反例定位/适用域。A0/A1/A2 都保持原版函数保留开启，不能把原有函数保留算成新增贡献。不要一次合并 A1/A2/新调度。

观察：关卡 2+ 的动作数、重复机制探索次数、失效函数复用、裁剪后的重复推理 tokens、完成权重、时间。若记忆文字增长、缓存命中下降，或原本能解的游戏出现持续退化，则撤回相应记忆模块；不以“摘要更漂亮”判成功。

## 3. 方向 B：面向信息增益的规则发现与局部规划

### 假设

智能体常在目标未确认时反复移动，或在大动作批次里错过关键反馈。保持多个可反驳的控制/规则/目标假设，用最小辨别动作获取信息，再用生成的局部模型规划，可能提升动作效率。

### 设计

每个待确认问题只保留少量候选，例如“推块到标记”与“让某色连通”。选择能区分候选的动作，并保存动作前后帧和动画证据。对象连通分量只是辅助观察，不能当确定对象身份；同色接触和暂态像素会破坏静态分割。

当候选规则足以解释已观察转移时，模型可写 `transition(state, action)` 与 `goal(state)`，在**自建模型**里做 BFS/A* 或有界搜索。执行短段后看真实反馈，模型不匹配就修正规则，不把错误模型的完整长路径盲目执行。

不能读取评测游戏内部状态、复制隐藏环境或通过反射获取规则。所有模型来自智能体实际可见帧、动作与反馈。

动作批次长度随理解程度变化：

- 未知控制/新物体：短交互，优先识别因果关系。
- 已支持的确定性移动：复用路径函数、较长批次。
- 达到新状态或跨关：重新观察，避免多走动作。

这不是新增一套审批门控，而是 agent 的探索与执行策略。基线已有动画、差分、动作停止机制，先检查它们为何没有被正确使用，再决定是否新增代码。

### 代码与实验

先在 `prompts.py` 和现有 Python 工具上下文内提供明确的假设/反例用法；必要时新增 `local_model.py` 供可执行模型存储与限时搜索。不要预制一套针对全部公开游戏的规则库。

B1：针对明确卡关类型，新增 2–3 个竞争目标及各自可区分的证据；查看动画、跨关继承和小探测原版已有，不能算新贡献。优先回答 sk48 类型的“运动模型对但目标错”和 lf52 类型的“最终帧掩盖关键反馈”。  
B2：在 B1 的真实轨迹确认需要搜索时加入局部模拟器。

记录：达到第一个正确目标假设前的动作数（需事后人工标注，不能自动可靠识别）、失败重试、每关真实动作、搜索计算时间、预测错误类型。若只有人工识别出的公开游戏获益，不能说明隐藏泛化提升。

## 4. 方向 C：评分感知、缓存感知的计算调度

### 背景

原版已经包含进展优先级、动作/token 消耗衰减及临近截止的远期价值衰减。不能把“加 scheduler”重复包装成新贡献。

### 假设

原版使用启发式常数。用开发轨迹估计不同进展阶段的边际收益，并计入切换时的冷 prefill 成本，可能在同一 9 小时内提高总分。

候选优先级（研究表达式，不是已拟合公式）：

```text
priority(g) =
 [P(在额外预算内过当前关 | 可见轨迹特征) × 当前关可得增量
  + 后续关卡的折扣机会价值]
 / [额外推理秒数 + 切换/冷 prefill 秒数]
 + 初始覆盖/探索项
```

隐藏人类动作基线通常不可观测，不得用私榜 h 值排序。用公开开发集的范围估计或仅可见特征作代理，并报告代理误差。所有游戏必须有初始机会；调度只在现有缓存友好边界或充分长时间片切换，不能逐 token 抢占。

### 代码与实验

拟修改 `priority_scheduler.py` 及其在 `tool_agent.py` 的调用，保留旧策略为对照。先从作者现有动作/token惩罚及 tail fade 做小范围改动，不立即训练复杂预测器。

在相同硬件、serving 与总墙钟预算下比较原版与新调度，tokens 作为资源结果另报；记录各游戏获配预算、未启动/饿死情况、后续关卡完成、cache hit、prefill时间、最终官方 score。离线重排只能作筛选：改变调度会改变可见轨迹，不能把重排分数当因果实测。

## 5. 前沿研究怎样转成可行实验

- **Tycho / Twin / PRO-LONG 等**：提取“可执行模型、证据与长程状态如何组织”的机制；逐篇看实际模型、成本和协议。不可把闭源高计算预算排名当本项目预期。
- **Kepler**：用其 transient-frame 与目标假设启发观察设计，明确其重放评测限制。
- **Astra 官方报告**：保留推理状态可能关键，但其成本和接口不满足本场离线约束。我们借鉴状态保留原则，不调用其 API 参赛。
- **Dreamer/通用 model-based RL**：本次剩余周期不把训练大型世界模型列主线。若未来有足够轨迹，可研究“下一步状态/目标机制”的轻量蒸馏。
- **旧 ARC 静态 TTT/程序合成**：只借鉴规则表示、推断和局部程序搜索；任务接口与失败模式已经变化。

准确论文 URL、读到的限制、结果可比性以 [frontier-findings](../../research/frontier-findings.md) 为准，避免在多份文档复制难以维护的“最新排名”。

## 6. 实验判断方式

以游戏为单位做同条件比较；不同 seed 使用新 session，并清空前次的持久记忆。公开游戏按机制家族划分开发/留出，优先整游戏留出，不能随机切分同一游戏的帧然后宣称泛化。

实验收益分开看：

1. 覆盖：完成关卡加权比例和游戏完成数。
2. 效率：真实环境动作、失败与复位的动作消耗。
3. 计算：wall time、prefill/decode、tokens、缓存及停机原因。
4. 迁移：后续关卡相对首关的表现、留出机制表现。
5. 官方分：本地官方 scorecard 与 Kaggle public LB 分栏，记录版本和日期。

本次公开档案的 100 条轨迹来自 25×4、共享一个 8h10m56s 的调度任务，不能视为 100 个独立样本或四次独立完整复现。新实验按游戏和独立运行区分相关性。

不做大量 seed 网格，不从单次小幅 LB 上涨下结论。先人工读有代表性的轨迹，再把稀缺 GPU 时间投入最能证伪假设的对照。
