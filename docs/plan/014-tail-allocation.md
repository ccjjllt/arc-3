# 014 全25游戏算力分配对照

日期：2026-10-17。用户已明确要求实施上一轮方案，并强调GPU配额有限、尽量提高利用率。承接[013计划](013-research-next.md)。本轮只运行首次baseline→tail对照，不占正式提交名额。

## 固定实验

25个游戏完整ID及顺序沿用005；baseline与tail_80k各7254秒、1 pass、10活跃流、warmup0。唯一候选差异是ARC3_PRIORITY_TAIL_LOOKUP：remaining→1；PACE保持0，所有旧研究干预关闭。配置：[014-tail-allocation.json](../../experiments/014-tail-allocation.json)。

两臂共用一次模型加载，分开CPU进程，组间确认缓存清理。预计约4.3h，硬限5h、启动上限1200秒；若启动挤占冻结预算则停止，不缩短比较。首轮未通过013预设晋升门槛时，不消耗倒序确认预算。

## 两臂共同工程变更

- 模型加载前运行独立CPU preflight：固定runtime hash、两种动态调度配置实际生效、deadline/timing/scheduler hook安装、snapshot和逆序恢复。无HTTP/模型/游戏动作。
- handover后、chat入口及每次transport前检查停止/截止；不改变截止前payload/timeout或已经在途的响应。两臂相同，不能算tail收益。
- 实际队列enqueue/reprice/selection事件记录有界snapshot、priority、候选及被选session；记录失败不改变调度。
- 每10秒GPU采样覆盖启动/两臂/收尾。观察工具不写每步磁盘、不增加模型调用；CPU开销仅用于筛查，不当GPU吞吐实测。
- 首组崩溃/未完整覆盖/worker未排空、模型服务退出、缓存未得到新的backend成功确认时，停止后续臂。清理整个自有进程组，包括主进程已退出但子进程仍活着的情况。

## 结果与后续

原始逐关动作独立复算AE，记录关卡、加权覆盖、全通、总tokens及逐游戏分配、真实排队选择、GPU利用率、模型启动/CPU/收尾耗时、取消边界。总GPU利用率高不等于有效探索增加，最终以固定预算下关卡和分数判断。

首轮均分/加权完成覆盖为正、总关卡不降且至少两个游戏新增关卡，才进一步评估倒序确认。方向反转或仅单游戏撑起收益不晋升；两轮确认后才讨论正式候选。原生变量015独立进行CPU准备，不混入本轮求解器。
