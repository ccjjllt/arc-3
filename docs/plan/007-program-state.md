## 第一阶段目标与假设（CPU，GPU预算0）

核实工具timeout/异常是否将此前已经成功保留的函数集合错误地清空。如果是，考虑在没有收到有效新定义快照时保留上一个成功集合；正常成功返回、显式变更和关卡/游戏重置仍按现有语义处理。

这是假设，必须先查实际源码和手动复现；不能仅根据“旧函数没了”就认定框架bug。保留函数也不证明后续就能过关。

## 研究与实现交接步骤

1. 对照005 tr87原始请求第133—151行，确认timeout、函数丢失提示与后续编码错误的先后关系。
2. 阅读tool_agent._record_retained_functions、python_tool_sandbox.run_sandboxed_python及retained_functions实现，区分未收到快照、合法空集合、新定义不合法、作用域重置。
3. 使用已有本地CPU环境和最小人工写的Python片段复现“成功定义辅助函数→工具超时/异常→下一次调用函数”的行为，不执行日志中的完整模型代码，不创建测试文件。
4. 写清若修复需修改的代码、旧函数与新函数冲突处理、正常删除/重置、错误后的真实游戏状态。不能回滚已执行动作，也不能把保留下来的旧函数当成已验证的当前关规则。
5. 仅在实际缺口明确后实现一个小的独立补丁；不同时引入全局变量持久化、目标提示、调度变化或世界模型。
