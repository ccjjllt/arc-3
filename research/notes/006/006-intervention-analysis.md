# 006：历史暂态摘要是否进入模型、是否被使用

本轮确认补丁在真实运行中工作，并找到模型实际引用摘要的例子。它不是一次“干预没有触发”的实验；但摘要被引用不等于帮助过关，也不等于整轮分数变化由它造成。B 总体低于 A，不支持把当前补丁直接并入默认求解器或原样扩大 GPU 实验。

对应计划：`docs/plan/006-transient-history.md`。全局成绩与资源分析分别见 `research/notes/006/006-results-analysis.md`、`research/notes/006/006-efficiency-analysis.md`；本文只分析信息通道与行为。结构化审计保存在 `experiments/006-analysis/intervention.json`。

## 1. 证据范围与口径

- A=`baseline`，B=`transient_history`，均来自已完成的 `runs/006-transient-history/` 原始输出。本轮源码与运行产物保持原样。
- 读取两组 diagnostics、benchmark、metadata；深读 B 的 tn36、lf52、su15、sc25，另读 A tn36 作为局部参照。不读取游戏引擎，不执行模型日志代码，不启动 GPU。
- compact 使用已修复历史裁剪问题的 `scripts/tools/compact_requests.py`，输出在 `runs/006-compact/`。消息以稳定 tool-call ID 去重，原始 JSONL 的行号从 1 开始，`source_message_index` 从 0 开始。
- 下文 `B lf52 raw61` 指 `runs/006-transient-history/transient_history/lf52-271a04aa_p0_requests.jsonl` 第 61 行。其余三个文件前缀分别为 `tn36-ef4dde99`、`su15-1944f8ab`、`sc25-635fd71a`；events 位于同组 `artifacts/`。
- raw 请求中的新 assistant 消息是此前完成的模型输出再次进入上下文。调用文本不单独证明动作发生；动作以 tool stdout、diagnostics 与 events 联合核对。`action_num` 使用真实 history/events 计数，不把用户提示里的显示 step 当作另一套动作号。
- 分四层陈述：本地附加；进入实际请求并得到响应；后续有具体引用/验证；对过关的因果贡献。前两层可以核对，第三层需要逐段阅读，第四层本轮没有固定轨迹反事实或重复实验。

## 2. 全量触发与边界审计

A disabled 的新增读取/捕获/附加计数全部为 0。B 观察 1,016 次 Python 调用：514 次没有新执行动作，401 次没有符合条件的较早暂态，101 次附加成功。模块 diagnostics 没有捕获错误或 history 匹配错误；这不表示原始 Python 工具没有普通运行错误，例如 lf52 raw61 仍包含原有 `StaleStateActionError`。

## 4. lf52：明确使用，也出现重复和动作归属混淆

**有具体采用：raw61 → 63 → 65。** raw61 同一 Python 调用执行了重置按钮、LEFT、RIGHT、DOWN；DOWN 的末帧无棋盘变化，后续点击被原有 no-op guard 阻止。附加 metadata 保留了 action37 LEFT 的 2 帧 / 29 暂态像素 / `[32,25,38,33]`，以及 action38 RIGHT 的 3 帧 / 44 像素 / `[32,26,38,36]`。events 第 56、57 行确认两个动作。

raw63 的新推理明确引用这些 bbox，把变化定位到橙色物体区域；随后没有把 bbox 当作最终证明，而是实际调用 `frame_diff(t.before_frame,t.after_frame)` 检查四条 transitions。stdout 返回 LEFT 中橙色 16 像素对象从 `[33,31]` 到 `[33,25]`，RIGHT 返回；raw65 据此建立“橙块可沿管道移动”的假设。这是摘要参与观察、引发真实历史帧检查的例子。LEFT/RIGHT 各有 122 个 settled changed cells 的 stdout 本来也可用，所以没有反事实证明只有补丁才能触发该发现。

**重复信息：raw115 → 117。** raw115 附加 action133–136，另明确省略 15 条。raw117 特别讨论 action134（19 帧 / 219 像素 / `[12,2,63,48]`），先称其可疑，随后将其解释为早已见过的重启图标出现，并写出 `Fine, no new info.`。动作19/20等选中与跳跃、重启图标出现、橙块往返的类似摘要反复出现；这不是技术去重失败，而是不同真实动作的语义信息可能重复。L2 最终仍未通过，不能由此推出重复信息导致失败。

**可迁移的证据归属缺陷：相同坐标的不同动作被回忆成同一证据。**

| 实际动作 | raw39 / events 中的事实 | 后续混淆 |
|---|---|---|
| action22，`MOUSE(17,39)` | 完成一次 jump；附加摘要 8 帧、45 像素、bbox `[12,27,18,40]`；events 第33行 | raw117、135 把该 bbox 用作“在 state C 点击 (1,5) 后”的 ghost 观察 |
| action23，仍是 `MOUSE(17,39)` | 下一次独立点击；stdout settled diff 只有 HUD 1 像素、无 appeared/moved；末动作原生提示为 3 帧、16 像素、bbox `[15,36,18,41]`；events 第34行 | 后来被上一个同坐标动作的 bbox 替代 |

raw41 最初正确区分了 action23 的 16 像素 ring flash。到 raw117/135，模型却用 action22 的范围论证“管道外不可能有 ghost”，并记成显示了一个左侧 ghost。真实 metadata 保留了动作号，混淆发生在后续回忆/推理中。两次观测都没有给出右侧 ghost，错误引用未必改变这个具体排除结论；它也不能证明游戏规则实际上允许跳出管道。但它说明仅提供 `action_num` 尚不能保证模型日后将证据绑定到正确的状态和动作。

暂态 bbox 本身也只覆盖变化后恢复的像素，不是全部 settled 改变或完整对象轨迹。raw63 一度把“有 transient”疑问化为“物体是否已回到原处”，随后利用 transitions 自行纠正。后续方案如利用 bbox 排除对象存在，必须仍回到该动作的真实前后帧；本文没有据此另叠提示。

## 5. tn36：首关改善发生在首次附加之前

B 从 1 关提高到 3 关是本轮结果；但 B 第一次附加是 **L2 action33**，在 raw53。B 的 L1 已在 action15 完成（events 第22行；A L1 用50动作）。因此“补丁修复005首关蓝按钮遗漏并让B首关更快”不受本轮轨迹支持。

B 的 L1 在 raw9 之后通过原生末动作提示看到蓝按钮暂态，raw11 读取 timeline，raw13/17/21 读取动画中的黄色物体位置，raw23 的动作完成首关。A 也看到了蓝按钮动画，早期更多聚焦扫描光标，后来重新点击以检查黄色物体。两个样本支持分析观察路径差异，不能将差异确定归因于直接附加，也不能确定排除共享服务调度的间接影响。

三个实际附加 episode：

- **L2 action33，raw53 → 55**：点击左侧蓝卡产生6帧、350像素、bbox `[16,6,50,25]`；同 stdout 已打印左侧形状从 `[16,22]` 到 `[16,6]`，随后灰卡旋转。raw55 的主要发现直接依赖这些 settled moved 信息；没有明确引用 action33 新摘要，可记为“收到，但独立增量/采用未确定”。
- **L3 action124，raw173 → 175**：两次卡片点击中只保留第一张卡的历史暂态；raw175 明确讨论该历史范围，并承认 `After card C: unknown`。它仍不能从范围恢复卡片 C/D 各自的完整位移/程序语义，随后转向右侧程序和当前动画的真实坐标检查。L3 后在 action151 完成（events 第219行），其间有多步实验，不能把通关归给这条摘要。
- **L4 action152，raw193 → 195**：第一张卡有5帧231像素暂态，第二次点击 no-op，第三次未执行。摘要确实保留了第一张卡；raw195 主要继续阅读 settled ASCII 以确认形状。该关只执行4动作后结束预算，未有过关收益证据。

005 的历史非末动作丢失问题有独立 CPU 复现；006 在这次 tn36 路径中没有重新遇到它的首关触发形态。两件事应同时保留。

## 6. sc25 与 su15：无增量、局部使用和模型更新分别存在

**sc25 L1 raw47 → 49：摘要没有增加已打印的观测。** 一次调用点击 `(20,14)`、`(19,25)`、`(20,30)`，代码逐次读取并打印全部 timeline。三次都是 keypad 红色闪烁后恢复，81 像素、4帧；附加的 action33/34 两条仅重复该 stdout 的帧数/范围。raw49 将其解释为错误反馈，但颜色与闪烁序列来自同 stdout，不能把该理解视为补丁独有贡献。

**sc25 L4 raw139/153/159/161：收到摘要，明确采用证据有限。** 这四次是缩小/传输动作的历史暂态；后续 raw141/155/161/163 主要依据当前 head 位置、剩余能量、墙/目标是否消失规划路线。raw161 的实验在两个距离尝试 M-transmit，stdout 给出 `(29,31):rwall`、`(29,29):CLEARED`；raw163 选择可在剩余17步内执行的14步路线，L4 在 action235 完成（events 第292行）。这是可见的距离假设→动作反馈→路线修正链，但无需把同一 payload 中的暂态摘要当成决策原因。B 只过4关、A过6关，不能因这几个摘要未被明确引用就断言它们无作用或导致退步。

**su15 大多数摘要与重复点击反馈重合，仍有显式使用。** 53条里48条为5帧；raw17（首关、首个历史附加之前）已通过坐标与真实 timeline 将常见环形动画识别为点击位置附近的 ripple。因此后续每次5帧并不自动代表新机制，但有时它和其他对象运动共同构成范围，不能统一删成“装饰”。

- L2 raw103→105 发现先前“进入圆才升级”的猜想与实际位置不符，随后 raw105→107 通过两点合并及对象列表验证 merge；raw109→115 继续组合出黄色物体并送入圆。L2 在 action65 完成，L3 在 action87 完成。关键证据是每次打印的 settled 对象颜色、大小、位置，而非单独的暂态条数。
- L4 raw137 附加 action88–90（events 第139–141行），同 stdout 也逐步打印粉色 glyph 位置。raw139 写出 `Actually the bbox in the transient events shows it`，随后又写 `that's the ripple+glyph ... can't tell`，并在下一段代码逐动作打印 glyph bbox。这是“被使用，但信息不足以分离运动对象”的明确例子。后续 raw155/165/181 多次看到合成物被降级，raw183 承认 UNDO 只撤销一动作、先前顺序记错；L4仍失败。摘要没有提供对象身份、每帧次序或攻击规则，不能据其存在认为敌人模型已经学对。

以上分类针对具体 episode，不是对所有58次调用机械打标签。`无增量` 指同一 stdout 已含等价或更细信息；`重复` 指后来又解释已知类型；`被用` 要有明确引用或验证链；`误用` 指能与真实动作/状态绑定核对出的错误推理。没有明确引用的调用保留“不确定”，不算“忽略”。

## 7. 研究取舍

1. **保留已证实的通道修复，不把它等同有效策略。** 006 证明较早真实动作的暂态可以在有限长度内送达，并至少在 lf52/su15 参与观察。全局描述性差值为 B−A 约 −6.46 分、−5关；一次 A/B、不同随机轨迹及共享模型服务不足以估计因果效应。
2. **003 和006失败位置不同。** 003 主要只有初始指导改变，marker 机制几乎未触发；006 已实际触发、送达、被引用。继续用“再强调模型注意”解释二者，证据不充分。
3. **暂不原样扩跑006，也不立即叠新提醒。** tn36首关不是本次正例，sc25有直接冗余，lf52有反复解释和证据归属混淆；还未获得一个可靠的、可重复的通关收益链。
4. **可迁移候选是动作证据归属与状态更新，而非更多摘要。** 相同坐标不代表相同状态下的同一种操作；暂态 bbox不等于完整结果。这次先记录缺陷，不另做提示补丁。下一轮优先由主研究记录中的函数持久化快照问题形成可 CPU 复现的单一修复；006保留独立开关，避免同时混入下一轮以模糊归因。

本报告没有执行“关闭某条摘要后仍运行相同模型轨迹”的反事实实验，也没有证明任何单一段落解释了全局回退。未审阅的3个有附加游戏只报告 diagnostics，未把它们的采用行为外推自这4局。
