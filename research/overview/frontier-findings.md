# ARC-AGI-3 前沿方法研究与可落实方向

研究截止：2026-10-10（Asia/Shanghai）。本文只采用论文原文、作者发布的实现/实验记录和 ARC Prize 官方资料；所有链接均于该日访问。本文是研究证据与实验建议，不是本项目已有成绩。未训练模型、未运行本文建议的对照实验、未提交 Notebook。

## 1. 结论与研究排序

**综合更新**：下表是论文与实现阅读形成的初始排序。随后对 Franzen 原始100条公开轨迹的重算，以及 sk48/lf52/tn36 日志分析，进一步支持把“目标假设与机制发现”提前为首个增量实验；最终执行顺序以 [002研究决策](../../docs/plan/002-strategy-improvement.md) 和 [003实验交接](../../docs/plan/003-next-experiment.md) 为准。函数保留和动画读取原版已有，新实验必须提出明确增量。

**主线：以最新可复现的离线 coding-agent 实现为起点，提高每单位 GPU 时间获得的有效交互推理，再加入轻量的证据检索、目标假设和按需可执行模型。** 以 9 月 Milestone 2 的公开实现为实用基线，7 月原始 Duck 只作历史对照。闭源大模型在公共集的接近满分结果说明架构方向有价值，不能当成本项目在 Kaggle 的预期成绩。

建议按以下顺序投入：

| 优先级 | 研究主题 | 主要假设 | 对拿牌的作用 | 当前证据 |
|---|---|---|---|---|
| P0 | 复现近期强离线 baseline，保留正确的图像、动画、动作与跨关信息 | 很多失败源于看不到/忘记信息或推理吞吐受限 | 建立可比较起点，避免从零开发造成巨大能力落差 | Milestone 2 作者实现与竞赛成绩，直接相关 |
| P1 | 可检索轨迹 + 持久代码 + 稀疏事件提示 | 高质量历史信息比反复自然语言总结更有效 | 减少重复探索与重复生成；覆盖长关卡 | PRO-LONG 对照 + 官方 frontier 分析 + 离线作者经验 |
| P1 | inference allocation：按进展与剩余机会调度 | 同样 9 小时，算力投给仍可完成的关卡更有价值 | 提升覆盖面及后段关卡完成率 | 已有离线实现；精确调度公式仍是启发式 |
| P2 | 目标假设与按需局部世界模型 | 能预测运动不等于知道如何赢；完整模拟器不是每关必需 | 解决“懂局部但不推进”“第二关重学” | Tycho、Twin、OPINE 各提供不同强度支持 |
| P2 | 基于分歧的主动探测 | 选能区分假设且兼顾推进的动作优于泛泛好奇 | 在真实动作昂贵时提升探索效率 | 理论合理；没有已核实的小模型 Kaggle 因果收益 |
| P3 | 可迁移宏技能与分层规划 | 将反复成功的局部程序参数化能减少搜索深度 | 减少长计划 token 与动作数 | TheoryCoder-2 的相邻环境证据；需验证 ARC-AGI-3 转移 |
| P3 | 合成互动数据、蒸馏、LoRA 或在线参数更新 | 小模型可学会“观察—假设—实验—修正”的过程 | 潜在中长期能力突破 | 本次未找到可信且可复现的本赛制增益，不能作为临近截止的唯一主线 |

不建议第一阶段投入：从零训练 Dreamer/MuZero/JEPA、全动作图穷举、要求每步重写完整模拟器、复杂多角色辩论、仅靠静态 ARC 的 TRM/HRM/TTT 成绩选架构。它们可能有研究价值，但当前缺少相对于强离线基线的时间收益证据。

## 2. 比赛本质对方法的约束

官方评分文档将动作效率写为人类动作数/agent 动作数的平方，单关封顶 1.15，按关卡序号加权到游戏，再对游戏平均。内部推理不计动作，但 Kaggle 推理墙钟预算仍有限。因此“真实环境动作”“内部计算时间”“完成了哪些后段关卡”是三个不同维度；不要只看总动作减少或已通关游戏的平均值。具体预算、提交接口以本仓库赛制调查及当前官方 evaluator 为准。[官方评分](https://docs.arcprize.org/methodology)

研究中必须区分四种任务：新游戏的首次理解；同一游戏后续关卡的机制迁移；目标未知时的探索；目标已知时的规划。一个方向可能只改善其中一项。尤其，观察帧可以隐藏状态，动画可以包含最终帧中不存在的信息；将游戏永远当作“最后一张图就是全部状态”会导致错误抽象。

## 3. 一手资料证据账本

“强/中/弱”描述证据对本项目决策的支撑，不是论文质量排名。公共集分数、半私有 API 分数、Kaggle 分数分别标明，不作同榜排序。

### S01 — 官方 frontier 能力与记忆干预

- 来源：[OpenAI's GPT-6 Astra on ARC-AGI-3](https://arcprize.org/blog/astra)，2026-09-03，ARC Prize。

### S03 — Duck 的方法来源

- 来源：[Tufa Labs 原文](https://tufalabs.ai/research/duck-harness/)，2026-07-01；[作者代码](https://github.com/Tufalabs/duck-harness)；[官方 Milestone 1](https://arcprize.org/blog/arc-prize-2026-milestone-1)，2026-07-06。
- 已读：架构、结果、代码仓库说明。
- 小型本地模型通过 Python REPL 操作游戏；图像和文字并用，短上下文不断淘汰旧消息。Qwen3.6-27B FP8 的公共集多次运行均值约 1.60，存在很大游戏差异；这是旧代模型与旧 harness 的结果。官方还记录了手制工具可能伤害其表现。
- 证据：证明 coding-agent 路线可在比赛里运行并获奖；不能沿用其旧模型作为今日竞争上限。

### S04 — PRO-LONG：先修记忆，再加复杂世界模型

- 来源：[论文](https://arxiv.org/html/2607.20064v1)，2026-07-22；[代码与日志](https://github.com/alexisfox7/PRO-LONG)。
- 已读：方法、工具梯度消融、workspace persistence、best@k 与成本说明。
- 全部交互写入结构化日志，agent 用搜索与 Python 查询。GPT-5.5 的工具阶梯分数为 23.1→27.2→38.3→41.2；有日志时清除其它 workspace 的影响小。97.4 是选择性 best@2，不是单次得分。
- 可借鉴：历史永久可取，活动上下文保持紧凑；先提供精确查询，再评估摘要。证据中强，但模型与资源均不匹配本赛道。

### S05 — Tycho：决定何时建模，比总是建模更重要

- 来源：[论文](https://arxiv.org/html/2607.28287v1)，2026-07-30；[作者代码](https://github.com/NIMI-research/Tycho)。
- 已读：问题形式化、四策略比较、成本/局限、作者 README。
- 同一 Opus 4.8 配置，直接推理/单 actor 建模/按需 builder/失败触发 builder 分别 79.07/85.36/88.49/83.07。自动修复预测更准确却行动更差。换更强模型的 100 分只来自 25 个公共游戏；每策略一次运行，不能当稳定因果估计。
- 可借鉴：模型可用但非必选；状态跨步推进；保留动画与终止事件。强于仅观察相关性，仍需本地资源下对照。

### S06 — Twin：将“目标错误”与“动力学错误”分开

- 来源：[论文](https://arxiv.org/html/2608.14490v1)，2026-08-14；[代码](https://github.com/Alexyskoutnev/TWIN-ARC-AGI-3)。
- 已读：方法、主结果、消融、Appendix C 成本与目标分析。
- 相同基础模型，现成 coding harness 61.1、Twin 93.3；完成 179/183 关。总计算 2.60B processed tokens、91.4 小时，不能原样搬进单 GPU 9 小时。论文指出拟合动力学后目标发现仍常耗费大量计算。
- 可借鉴：单列 goal candidates、用反例更新；只对模型支持的有限范围规划。不要为了复刻论文而要求每次真实行动之前全历史精确复验。

### S07 — OPINE-World：对象类型本身也是假设

- 来源：[论文](https://arxiv.org/html/2607.01531v1)，2026-07-01。
- 已读：对象建模、ontology error、主动探索、实验与局限。
- 作者报告 20/25 游戏、160/183 关、78.4 RHAE。模型按对象类型分解，用不一致的动作效果寻找错误类型划分。论文无充分独立组件消融；可观测 Markov 表示是假设，隐藏状态会使诊断持续报错。
- 可借鉴：保留多种分割/类型解释，点击与移动探测针对有分歧的对象。不可认定颜色连通块天然等于真实对象。

### S08 — 可执行模型组件研究：有帮助但需要付费

- 来源：[Do Coding Agents Need Executable World Models...](https://arxiv.org/html/2607.15439v1)，2026-07-16；[早期工作](https://arxiv.org/html/2605.05138v1)，2026-05-06。
- 已读：嵌套消融、fixed-interface treatment、后续模型对照、局限。
- GPT-5.6 Sol/xhigh 文本模型 92.34、verification treatment 98.97；成本代理约 32.32M→90.75M。处理组同时改变接口、工具、模板及简化，不能说收益由“加一个验证提示”产生。早期工作仅 32.58，更说明模型/版本/协议应一起报告。
- 可借鉴：对局部模型做观测匹配可提供学习信号；但按相同时间预算比较，否则更多计算会被误认为算法收益。

### S09 — Kepler：最新但 headline 不宜作为竞赛标杆

- 来源：[论文](https://arxiv.org/html/2610.00834v1)，2026-09-30。
- 已读：方法、§3.1、结果、观察案例、失败分析。
- 摘要给出公共集 server-verified 100.00，但正文 §3.1 明确说明本地 discovery/final-replay 协议不同于官方首次接触预算，不能解释成官方 first-exposure leaderboard 结果。该限制比“已由 server 验证”更重要。
- 借鉴限于动画证据和预测/目标分离；不把最终重放动作数当全部学习成本，不以其 headline 设分数目标。

### S10 — TheoryCoder-2：分层技能为后续研究

- 来源：[Learning Abstractions for Hierarchical Planning in Program-Synthesis Agents](https://arxiv.org/html/2602.00929v1)，2026-01-31。
- 已读：抽象学习、库复用、环境/结果与讨论。
- 从经历生成可复用的高层 operators，再落到低层 world model。实验在 BabyAI、Minihack 和 VGDL 等环境，未证明 ARC-AGI-3 私有集增益。
- 可借鉴：成功子程序参数化，携带适用条件、结束条件、动作代价。P3；先做同一游戏跨关复用，再研究跨游戏迁移。

### S11 — Graph exploration：可作为便宜对照，不能把预览成绩当新赛制成绩

- 来源：[Graph-Based Exploration for ARC-AGI-3](https://arxiv.org/html/2512.24156v1)，2025-12-30；[作者代码](https://github.com/dolphin-in-a-coma/arc-agi-3-just-explore)。
- 已读：摘要、图探索与局限。
- 视觉分割、状态图、寻找最近未尝试的 state-action；六游戏预览集 median 30/52 关，不能与当前 25 游戏 RHAE 横比。
- 可借鉴：少量 state/action 去重与导航。全图搜索常需要真实探索动作；没有世界模型时便宜计算不意味着便宜交互，纯像素 hash 还可能合并不同隐状态。

### S12 — 官方失败轨迹：研究应直接针对失败机制

- 来源：[Analyzing GPT-5.5 & Opus 4.7](https://arcprize.org/blog/arc-agi-3-gpt-5-5-opus-4-7-analysis)，2026-05-01。
- 已读：160 次 replay 分析的三类失败。
- 局部效果理解正确但整体规则错、误套熟悉游戏抽象、过关却没学到跨关机制。本文后续实验用这三类失败定位收益，而不满足于“看起来推理更长”。

## 4. 推荐实施的具体机制

以下是本项目建议，均尚未证明有效。每项应作为一个可单独开关的研究变量，不先扩张成庞大框架。

### R1：稀疏事件记忆与可检索原始轨迹（P1）

最小数据记录包含：动作、动作前后最终帧、该动作的中间帧、level/attempt 边界、可用动作、结果标志、时间和 token 花费。保留原始数组；不要只保留 LLM 对它的描述。活动上下文放最近动作、变化摘要、已支持/被推翻的规则、当前目标候选；更老证据按需读取。

提供小而通用的查询：按动作类型、变化区域、level、失败前若干步检索；比较两段转移；查看 transient pixels。功能是让模型便宜地找到证据，而非预设游戏含义。函数保留和变量生命周期须清楚，以免上关坐标留进新关。

反证实验：同一基线、模型、推理时限，对比原上下文、仅摘要、日志检索三组。若日志检索增加大量工具调用但未减少重复动作/跨关重学，优先简化查询接口，不能仅以日志完整宣称有效。主要观察后段关卡完成、死路重试、重复实现函数的 token，以及全套游戏分数。

### R2：目标假设小表 + 信息动作（P2）

当 agent 能解释局部运动却无法推进，要求只提出 2–3 个仍与观测相容的目标，例如“到达特定关系”“消去特定对象”“匹配形状”；每个目标写出支持证据、能推翻它的具体观察、当前最短可行探测。不能给颜色强行赋予永久语义。

候选探测排序采用可解释的启发式：区分假设的能力 + 预期推进 − 真实动作成本 − 不可恢复风险。先不拟合复杂概率。优先选择同时推进并区分假设的动作；可用 UNDO 也要计费，并先验证它在当前游戏的效果。

反证实验：保持总推理 tokens 相同，与“多想一步”的普通提示比较。若能提出漂亮假设却没有更快首次过关，说明额外表格只是格式成本。记录每次探测后实际排除了哪个假设；没有排除证据的动作不可事后称为有效实验。

### R3：按需生成局部模型，CPU 搜索替代重复 LLM 出动作（P2）

启动条件用行为诊断：已见重复机制、已过一关但新布局规划困难、能写出简洁确定性转移；不是固定每 N 步强制生成。只建决策相关子系统，例如运动/碰撞/旋转/连锁传播中的已知部分。状态可含历史计数、镜头位置、被遮挡对象，不能每步只从当前图重建。

模型最小接口建议为 `encode(observation, memory)`、`step(state, action)`、`goal_candidates(state)`；有限深度 BFS/A* 或 beam search 在 CPU 里搜索，真实行动执行短前缀并接收新证据。若目标未知，就保留 actor 直接推理。预测不符用于改假设，不建设完整门禁系统，也不新增测试文件。

反证实验：直接 actor、可选模型、强制模型三组，固定模型和墙钟；必须比较完关率与模型调用耗时。若模型只复制已经发生的转移而不能预测下一步、或提高拟合却降低成绩，应撤掉强制模型路线。关后模型准确度不能替代当时动作前模型是否可用的记录。

### R4：算力分配围绕分数增量（P1）

先继承强 baseline 的调度，再只改变一个信号。候选新信号：最近一次机制突破、短期完成率、反复同类无效动作、目标已明确但计划尚未算完。给每个新游戏最低探索额度，避免早期高方差导致饥饿；后半程优先可完成关卡。

调度时间片应与 prefix cache 生命周期协调，不能频繁切换导致重新 prefill。评分收益估计与 token 吞吐要分别记录；“tokens/s 更快”并不自动等价“完成更多关卡”。任何 human baseline 仅在当前接口公开可见时使用，不能把仅供计分的未知信息注入 agent。

反证实验：固定总 wall time 下比较公平轮转、原调度、新调度；同时看最低探索覆盖、后段关完成率、cache hit 与有效生成量。若分数提升来自个别容易游戏反复被分配、但覆盖崩溃，要保留原调度。前几次只使用宽松启发式，不提前训练精细 bandit。

### R5：微型技能库与迁移（P3）

先仅保留模型本游戏已经写出并成功使用的函数，再考虑抽取宏技能。宏技能需参数化对象/坐标，写明前置条件、停止条件和预期效果；边界变化时返回控制，避免跨关执行旧动作串。

反证实验：单纯函数保留 vs 自动技能抽取。在相同 token/时间预算下比较重复代码、规划深度和失败恢复动作。若没有超越函数保留，暂不引入 DSL/PDDL 或跨游戏 retrieval。

### R6：训练方向只做小规模可证伪探索（P3）

将 test-time learning 分成两件事：当前推荐的是固定权重下更新规则、证据与程序；参数更新属于另一条尚未验证的路线。公开游戏不足以直接支撑大规模从零 RL。若以后训练，优先目标是工具调用、画面差分理解、反例修正规则、保存跨关技能，而不是背诵游戏 ID 与解序列。

可做机制组合生成器，训练集和留出集按机制组合/渲染风格划分；教师只能依观察与动作产生轨迹。蒸馏也要保留发现过程和错误恢复，不能只学成功尾段。用等计算资源的原模型作对照。合成任务改善但未见游戏迁移时，不宣称提升本赛能力。

## 5. 人工实验记录规范

遵守用户要求：不写测试文件，不做以门控工程为中心的路线；实验通过手动执行 Notebook/命令并人工读轨迹。必要的在线预测对照是 agent 学习机制，不是要求另建软件测试体系。

每轮只回答一个研究问题，保存：模型/量化和 serving 配置、代码版本、游戏版本、种子/重复次数、墙钟/token/真实动作、逐关完成与分数、代表性失败轨迹。代码完成和效果分开。失效实验也写进对应 progress，不能将多个合并改动的联合提升归因于其中一个。

公共集仅 25 游戏且模型可能见过其资料，因此同时使用完整公共集覆盖、按游戏留出的本地研究划分、少量诚实的 Kaggle 外部反馈。不得将 best@k、先发现再重放、不同基础模型成绩混入单次公平对照。探索时看 failure modes，最终选择看保留的首次运行而非最好看的一次。
