## 主线 A：020 精确状态通道

问题是程序已经获得正确像素，模型写搜索代码时再次手抄并引入错误。把 008 读取器接到现有 Python 工具的 `current_frame`，不再增加需要另行记忆的缓存工具。

已实现接口：`current_frame.region(bbox, foreground=...)` 与 `region_from_node(node, ...)`（传当前分割节点字典）。返回原字符矩阵、全局原点、显式前景 mask、像素坐标及帧来源。推荐同一次调用完成：

```python
region = current_frame.region((top, left, bottom, right), foreground={color})
plan = solve(region.cells)  # solve 直接消费读出的值；不要把矩阵重新手写一遍
```

框坐标采用 `(top, left, bottom, right)`，四边端点均包含；像素坐标为 `(row,col)`。保留正常历史值与计划，旧帧对象的实时 getter 则报过期，避免行动后误认旧观察为当前观察。可见 mask 仅表示显示像素，不能自动当作真实碰撞足迹。

第一轮：12 个官方已知开发游戏，baseline → grounded_state，各 1800 秒，10 路服务容量，共享一次模型加载，整体硬上限 5400 秒。采用原有预算、缓存与排空设施，不把 018 的提示、015 的变量保留、执行检查、FP8 同时叠加。该短筛用于快速产生候选，不是全 25 游戏最终回归，也不是新游戏泛化证据。

首轮关注两件事：同预算结果如何；实际模型是否把 region 的值直接喂给求解函数。若只打印区域再手抄，说明通道尚未充分采用；应改连接方式，而不能把工具调用次数当成功。若收益集中于少量游戏，只做足以区分机制与偶然性的有限复核。

## 主线 B：预测失配停批

独立实现 `checked_execution.py`，先不与 A 同时改变。模型给出已有预测函数及可观察状态提取函数；动作保留完整 payload，包括点击坐标。

每一步：冻结预测 → 执行一个真实动作 → 先检查结束/跨关/重置 → 比较同一可观察投影 → 首次失配立即停止剩余动作，将反例返回模型。未知、异常和不完整提取必须明确区分，不默认当作预测成立。无额外模型评审，也不添加免费 UNDO 或回滚。

只比较模型声明能够预测、能够从合法观察读取的部分；全像素差异不等于物理规则失配。动画暂态不稳定时，先采用低歧义字段或让提取器返回未知。未知停批可能降低吞吐，必须在在线候选中观察频率。

已知 m0r0 例子是 18 动作中第 2 步首次失配后仍继续余下 16 步；不能把 16 步直接写成确定节约，因为后续动作不一定全部无效。参考 Sujan 的机制，保留我们的边界处理。Franzen 本来已有 no-op/stale/terminal guard，本改动针对的是显式预测失配。

## 主线 C：有限替代目标／规则探索

在同关多轮无进展、搜索反复无解或出现已知规则无法解释的真实反例时，允许一次重新提出竞争假设。保留真实观察、已验证事实和有效函数，不粗暴清空正确知识。

最多两个仍符合证据的解释；选择 1–3 个能区分它们的真实动作；根据反馈修正规则后继续规划。计入正常动作和运行预算，每关至多一次，RESET 不返还次数。首版额外模型调用建议最多一次并限制输出预算，避免持续反思。具体触发与模型提示尚须接入 Agent；独立预算账本完成不代表探索候选完成。

OPINE-World v3 的 78.40 → 58.16 是 Opus 4.8 下移除完整 Bayesian 探索层的消融，不能当作这套小机制的预期涨幅。迁移的是竞争假设与实际探测的过程。
