## 两条直接链，以及不能夸大的损耗

**009 cd82：正确输出 → 数字被换位/误记 → 重新查图并重写提取器。**

1. [requests L37](../runs/009-v2-smoke/cd82-fb555c5d_p0_requests.jsonl) 的真实工具输出给出当前灰框 30 pixels、行 45–53、列 25–38。对应 [events L34](../runs/009-v2-smoke/artifacts/cd82-fb555c5d_p0_events.jsonl) 的 action 21。对保存公开像素作独立诊断扫描，重新得到同一个范围和数量。
2. L39 把结果说成行 30–45，L41 又明确写“stamp_state() printed … 43 px rows 30-45”。这些数字不是工具实际给出的当前元组。模型据此提出帧仍处在旋转动画、segmentation 极值有错等解释。
3. L39 的动画读取返回 `nframes 0`；L41 再查当前 ASCII；L43 重写 `read_state()`，输出又回到原先已经正确的范围和 30 pixels。L43 仍把先前问题归咎于 segmentation。
4. 这段有 3 个额外检查/重建工具调用，没有据此确认新增动作损耗。对应 response L38/L40/L42 总生成 4,567 tokens，其中也有有用的姿态推理，因此**不能把 4,567 全记作缓存可节省量**。

这是证据使用失败，不是 mask 工具少提供了正确像素。它也不证明一个新存储 API 会被模型使用。005 同游戏 events L73（action 51）后来转向列举实测状态与转移，之后到 action 54 完成首关；这给出一种有用工作方式，但不是“加表就成功”的受控实验，不能将那一局的后续观察注入 009 较早状态。

**010 ft09：正确像素位置 → 错误手算逻辑列 → 11 动作批次 → 承认列号错误并重做覆盖。**

1. 候选 [requests L23](../runs/010-retrievable-animation/retrievable_animation/ft09-0d8bbf25_p0_requests.jsonl) 的 segmentation 正确显示当前图块位置；L25 在同一段中也列出列带 `[12,20,28,36,44]`，并确认 A/D 的像素起始列为 28。
2. 模型同时把 A/D 手工标为逻辑列 1；按它自己列出的列带，零起点索引应为 2。读取像素是对的，像素到逻辑标签的转换错了。L25 的打印标签又把错误逻辑坐标附在正确的小图案旁边，后续推理把这个标签当作事实。
3. L29 执行 11 个动作，未完成该关。L33 才明确承认：`Oh no. I mis-assigned map columns.`，重新计算覆盖及后续修正计划。
4. 可确定的是“11 次动作在错误几何假设下执行”，**不是 11 次都可避免**：符号含义也在变化，后续 13 动作计划还包含另一个未证实规则，不能把所有探测费用归给列号错误。

此例比纯抄写更严格地限制了候选：如果模型把错误逻辑标签原样存进缓存，它只会更稳定地保留错误。必须是程序计算的结构化值进入后续程序，而不是给自然语言猜测盖上“verified fact”标签。

## 真正的接口缺口与最小候选

底座已有全部 settled history、frame diff、segmentation、跨关函数源码保留，以及候选 010 的旧动作帧检索。它不是“没有记忆”。但每次 Python 调用建立新的 `runtime_globals`；只恢复可保留的 def/import，普通计算后的 dict/list 不跨 snippet。数据若依赖普通局部变量，函数会因 unavailable dependencies 被拒绝；模型通常重新读取、重算，或把 stdout 内容手写成下次代码里的字面量。

来源：[sandbox 初始 namespace](runtime-bundle/src/ARC3-Inference/inference/agent/python_tool_sandbox.py:354)、[函数恢复](runtime-bundle/src/ARC3-Inference/inference/agent/python_tool_sandbox.py:650)、[宿主只提交函数源码](runtime-bundle/src/ARC3-Inference/inference/agent/tool_agent.py:4614)。在 ft09 的实际日志中，`crop`、`sub` 就因依赖局部 `a` 而未被保留。换成接收 frame 的纯函数可以解决部分重复读取，**这一点基线已经能做到**，无须新工具。

候选只补**计算值原样跨调用交接**，不增加观察信息，不自动写自然语言摘要，不生成状态图，不推断正确答案。暂用说明性 API 名：

```python
# value 是当前工具代码已经算出的 JSON 数据，不从 stdout 重新手抄。
current_data.put("measurement", value)

# 下一次 snippet；只有观察身份仍匹配才给出 value。
entry = current_data.get("measurement")
if entry["status"] == "current":
    value = entry["value"]
```

第一版只做当前 observation 生命周期，**不做 game/level 持久事实库**。宿主为写入绑定 session、RESET attempt、真实 action_num、level 和 frame hash；同帧不同 snippet 可以取值。任一实际动作，包括 no-op、RESET 或过关，使旧值失去 current 资格；读取返回明确 stale/missing，不能静默把旧值当当前。先不提供历史值读取，旧事实仍可经既有 history / 010 原帧查询后重算；因此它不承诺减少所有跨动作的静态布局计算。

该身份只能证明“写入发生于哪个观察”，**不能证明 value 的数学或语义正确，更不能证明它确实由该帧计算**。元数据应叫 `written_at`，不用 `verified`。也无法阻止模型在同一长 snippet 中继续拿已返回的局部 dict 作用于动作后的新状态；失效保证只覆盖新 API 查询，不能宣传为任意 Python 对象的自动防陈旧系统。

用显式 put/get 而不是完整 namespace 快照，有两个目的：无需序列化 frame、可执行对象或第三方对象；同一个函数可继续复用，但当前参数值必须从明确身份的数据记录取得。候选工具说明只介绍这个数据生命周期，不额外添加“多反思”“系统枚举机制”“优先尝试某类动作”等策略，以免一次混测多项因素。

这和“提示模型把测量值放进纯函数返回值、避免手抄”有重叠。如果观察到模型已经持续直接调用提取函数，而没有跨 snippet 数据丢失或重打字，则本候选并无额外信息，应停止包装成大工程。尤其 cd82 的错误发生在自然语言解释层；即便原值可以取回，模型也可能不读或读后仍误用。

## CPU 前置合同与否决条件

以下是下一步的手工验证清单，**本次没有实现或声称已通过**。只用人工小型 JSON 和已保存公开帧，不执行轨迹代码，不新建 tests/CI。

1. **跨 snippet 精确交接：** 在真实 ToolAgent/sandbox 中保存计算出的嵌套 JSON，下一次调用逐值、canonical hash 完全一致；后续程序使用该值，无须重新输入整个字面量。宿主与 child 不共享可变别名，修改读回副本不暗改存储。
2. **身份失效：** 同 session、同 step/level 的新 snippet 命中；真实动作后及 RESET/过关后旧值无 current payload。相同数字 step 的另一 session 不能命中，当前帧文件和动作计数不会因读写缓存变化。跨关只复用函数逻辑，不自动复活旧数据。
3. **明确提交：** put 采用一次验证后的原子 JSON 副本；拒绝的更新不覆盖旧合法值。硬超时前若 put 已获宿主确认，记录是否保留须明确且能按当前真实状态判定有效；未确认的写入不得猜测提交。动作不能回滚或重放。不要复制 007 的“缺键等于空集合”问题。
4. **有界数据：** 第一阶段可取 16 KiB/value、64 KiB/session、32 keys 作为保守 CPU 检查上限，不视为已优化参数；拒绝对象、函数、非有限浮点和过深/过大的结构，不截成半个“正确值”。字节上限与 Python RSS 分开测量。
5. **原行为与成本：** disabled 时原提示、工具结果、函数保留、动作接口不变；启用后没有额外模型调用、自动数据回显或检索动作。计量 put/get、命中/失效、保存/读取字节、CPU 时间和输出 chars，不把 key 被保存等同于模型采用。

工程合同任何一项失败，不做模型 A/B。合同通过后仍只支持数据交付。采用证据至少要出现“程序计算值→保存→后续 snippet 读取原值→规划/检查直接消费”完整链；只保存人工猜测、只打印 key 或只增加重复读取均不算。

若有调用却继续出现相同误抄/错误推理，或只减少轻量重算却增加 prompt/token 和工具开销，则当前机制被反证，应停止扩跑。若效果只出现在一个已知病例、关卡没有净改善、控制游戏有明显资源性回退，也不晋升。后续实验只能在先固定底座后增加这一个开关；不能与新调度、008、新世界模型提示或 game/level 记忆同时开启，再把总分归给其中一项。

## 前沿证据只支持边界，不提供本地收益保证

本次沿用已核对版本，没有刷新外部榜单或重复大范围检索。[Tracing the Thoughts §4](https://arxiv.org/html/2610.11450v1) 描述跨关硬编码值的负迁移，以及把值改为参数的病例，但 7 次异构运行不是同条件随机消融；它不能证明本地每个硬编码错误都来自函数保留，也不能给本缓存一个可预期提分值。

[PRO-LONG §2–3](https://arxiv.org/html/2607.20064v1) 的程序查询工具阶梯支持可访问证据；workspace 清空 41.2→40.7 的结果反而限制了“更多持久笔记就是核心收益”的解释。其模型、动作上限和成本不同于本地 Flash-Next 预算，不能直接迁移效果量。详细核对保留在 [010 frontier update](010-frontier-update.md)。

已读本地 [Helios scoped_memory.py](notebooks/2026-10-13/heliosli-update/extracted-assets/scoped_memory.py) 与 [patch_scoped_memory.py](notebooks/2026-10-13/heliosli-update/extracted-assets/patch_scoped_memory.py)：它提供 game/level/step JSON 生命周期、有限值约束及快照提交，这是有用的接口先例；现有材料只有 CPU 检查，未证明 GPU 配对收益。它的范围更宽，模型放错 scope 仍可能固化陈旧假设，局部别名也不会自动失效。因此本建议只研究当前观察计算值交接，不复制整包、不默认采用其容量和提交策略。
