# ARC-AGI-3 — Prediction-guided action batching

Variant: **diagnostic**. Build SHA-256: `d8cb984eb7ea2e96e3e4b9799fdc9efdb2b3f88ef78e229ce798da2466759b82`.

Phase A performs a synthetic contract check and writes an explicitly labelled placeholder. Phase B connects to the official gateway, uses one scorecard and one instance per game, then validates the gateway-produced parquet. No Kaggle result has been obtained locally.

The diagnostic variant is a CPU engineering baseline. The model variant requires licensed public weights, compatible offline vLLM wheels and verified GPU memory before use. Own source is MIT-0; third-party licenses remain in effect.

## Deployment record

This notebook deploys the CPU diagnostic policy with the adaptive controller, seed 17, 400 client actions per game, and a 120-second game limit. It uses the competition-provided arc-agi 0.9.8 and arcengine 0.9.3 offline wheels. Compatibility checks passed 48 behavior tests and runs on all three known development games before upload. Those games are not a held-out evaluation.

The separately reported fixed Qwen3.5-4B 4-bit study ran on a local Apple Silicon computer through MLX. That model is not executed by this CPU notebook. The official Kaggle score must come from Phase B; the Phase A artifact is explicitly a placeholder and is not a score.

The experiment does not establish batching effectiveness. The local LLM produced single-action plans and supplied no multi-action queue intervention. Own code is released under MIT-0; third-party licenses remain applicable.
