## 机制证据

CPU 演示确实证明了 region 值能直接进入程序，但在线模型是否采用是另一回事。候选 `ar25` 的完整日志有 94 个去重 Python 调用、94 个结果，**没有调用 `region` / `region_from_node`**。它使用原有 ASCII 解析与自己编写的提取函数；多完成一关不能归因于新通道。

该轨迹仍出现错误区域／形状编码及把搜索位移当成绝对坐标的问题，部分后来被模型修正。通关也不意味着全部状态表示正确。细节见 [ar25 采用审查](020-ar25-adoption.md)与[主要退分轨迹](020-cd82-ft09-review.md)。

全12局候选日志已静态提取，共 **720 个唯一代码调用**。仅 `r11l`、`bp35`、`cd82` 的12条调用代码中出现新API语法；没有看到 `region_from_node`。这不是12次成功执行：代码含循环、函数定义及报错后未到达语句。全池做的是检索与别名核对，语义深审集中在重点游戏，没有声称逐条判断720段求解逻辑。

其中 `r11l` 有真实消费：`region.positions()`筛选候选点击位置后执行了MOUSE，反馈为NO-OP；`blocked_mask(current_frame)`还被保留并在后续动作后复用作诊断。因此不能把本轮归结为“接口完全没用”。与此同时，四位置参数调用和历史帧读取受到接口拒绝，说明仍有使用摩擦。见[全池索引](../experiments/020-analysis/adoption-index.json)、[r11l数据流证据](../experiments/020-analysis/r11l-adoption-note.md)。该局分数28.57→4.76，真实消费不等于收益。

cd82的末响应已通过完整请求身份字段从fallback文件唯一匹配补齐；未返回的请求、未进入后续历史快照的代码不虚构为已执行。原件、去重规则、覆盖范围及限制都在索引中。

当前结论有两层：**这个可运行候选的整体表现明显更差，因此不提交原版；准确观察直接进入程序这一机制尚不能由此宣判无效，尤其未调用接口的游戏根本没有检验它。** 也不能反过来说“只要强制采用就一定提分”。

## 接续决定

不自动重复 020，不扩大到全 25 或冻结社区集，不执行已准备的同版本正式 Notebook。保留 `grounded_state.py`、008 reader 和真实沙箱示例作为后续材料。

下一实施重点是：把已经存在的预测函数与真实动作反馈接起来，使失配确实停止错误后缀；状态通道则降低使用摩擦，并用实际执行的数据流证明它替代了转抄。社区统一 Agent 桥接、有限探索尚需实现。具体文件、顺序、运行命令与完成条件见 [实施交接](../docs/handoff/021-implementation-handoff.md)。本轮按用户要求交接，不启动下一批 GPU 或正式提交。
