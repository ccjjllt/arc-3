## 5. B线：033独立验收后接管动作的程序纠错

B首版目标是：**让028/031中“执行成功却仍填错像素”的程序被通用检查拒收；修订通过后，让真正的下一步行为使用修订产物。** 不从“编译成功”直接跳到“程序可信”。详细接口审计见[控制器纠错技术附录](controller-repair-boundaries.md)。

### 最小闭环

| 环节 | 由谁负责、必须留下什么证据 |
|---|---|
| 触发 | 优先沿用连续不同Python调用出现未恢复异常，或有来源的结构化预测失配；记录调用ID、观测ID、游戏/关卡/尝试。首版不因一次普通异常或单纯“很久没过关”自动修复；循环停滞触发须另行定义并测误触发 |
| 生成 | 请求一个明确的局部修订，如`extract(frame)`或现有预测函数；返回代码、入口、输出合同、适用范围和依赖。无需每次重写完整extract/step/plan；无可执行或可验证产物就结束事件 |
| 暂存 | 在隔离sandbox的临时命名空间执行。验证阶段宿主强制禁用真实动作；现有028动作拦截可复用，但031普通sandbox仍可调用action，不能直接当只读验证器 |
| 独立验收 | 宿主依据当前真实像素、已发生的完整动作及其结果检查。像素集合要比成员和覆盖范围，不能只比数量；转移预测必须在结果出现前冻结，禁止候选提取器与模拟器共享错误后循环自证 |
| 提交产物 | 验收通过才原子替换候选函数/数据并记录hash。旧028可能在报错前已覆盖`_kept_functions`，须补暂存与回滚，不能只还原callback就称恢复成功 |
| 执行与反例 | 宿主接管一个已提出、合法且有非空有意义预测的动作，或短计划首步；一步一观察，失配、未知或边界变化即停止余下动作。修订送回上下文不等于确定消费 |

现有`checked_action`将失配写入stdout/异常，`program_repair.failure_signal`却期待结构化的`status/expected/observed`；两者目前没有直接事件桥接。第一版必须补齐这个连接，不能只同时安装两个模块就宣布闭环。ft09的静默像素错误也未必触发Python异常：手工切点成功仅是机制证据，自然运行还必须证明存在实际可获得的触发信号。

验收通过只证明程序符合已检查的观测。恒定字段、空预测、无关HUD或代码自报`verified=True`都不足以放行动作；不能把同一反例既用于写修订又称为独立新样本。后续真实新转移用于确认，范围外的规则仍未知。

普通状态和已验证计划按游戏、关卡、宿主记录的重开/死亡事件、观测序号及程序版本管理。RESET后关号可能不变，也须失效；没有公开attempt ID时用宿主真实事件计数，不能虚构引擎隐藏状态。动作已经执行后发生超时，保留真实新状态并停止后缀，不能自动重发或宣称回滚了环境。

### 限额与晋升

初版可沿用现有成本上限：每游戏1个事件、事件内最多2次修订请求、每次最多4096输出token/60秒、事件总计120秒、剩余不足180秒跳过。编译、执行、检查、失败及主模型后续消耗均包含在同一候选墙钟内；这些是初始限额，非最优参数。若实际入口无法在此预算完成，就缩小修订对象，不先扩大到整套世界模型。

先用旧ft09错误提取器检验**通用检查能否拒收**，再用已有切点做一次真实模型纠错对照；每会话250秒/30新增动作的旧窗口可作为起点，但要留出修订后行动的时间。随后必须覆盖一段自然触发与一段正常轨迹。不把研究者已知的P4坐标/正确值、后续轨迹或引擎规则源码写入线上触发和修复提示。

**B线停止点：** 无法定义独立检查；旧错误仍被验收；修订通过却没有进入实际动作；只有手工切点可触发；或成本抵消收益。对应状态应如实写为“合同未成立”“在线覆盖未解决”等，不以继续反思提示填补。

推荐资源安排：A的配对窗口各约1800秒，B的配对切点使用250秒真实续跑及明确的恢复/收尾余量；最终时限必须在首次启动前冻结。若A已就绪而B仍未形成有效合同，A按时进入验证，B的CPU设计继续，不为凑“一次加载”无限推迟有效候选。

## 7. 从能力证据到正式submission

### 完整25题比较

选出一个有实际增量的候选后冻结实现，以009为对照做25题、每臂7254秒、10 streams。对齐正式的`warmup=1`、原请求行为、模型和服务；额外修订请求及记忆处理计入候选预算。研究OFFLINE、缩放预算、全局soft_end、日志及启动方式与正式长运行仍有差异，逐项记录。

主指标为官方计分公式下的25题平均分；同时读每题分差、关卡深度、动作效率、全通、时间/token及异常。后关权重较高不意味着只看总关数；动作效率也属于评分。最大获益与最大退化题都要看，并结合历史基线波动判断。

| 结果 | 决策 |
|---|---|
| 有效运行但无净增益或明显退化 | 关闭该版本，不原样正式提交 |
| 正收益，能追到记忆/纠错带来的实际改善，无明显运行问题 | 进入候选自己的GPU save并及时正式提交 |

| 漏题、预算不齐、崩溃或排空失败 | 标记运行无效；修具体故障后最多补一次有效对照 |

不要求每个辅助指标上涨，不设任意“至少+10分”门槛；也不把单轮正均值称作统计显著或私榜增益保证。候选单独成立之后才考虑组合，首个提交无需等待A+B叠加实验。
