AE 不是简单“过一关加固定分”。第 i 关的权重为 i，关内分值为 `min(115, 100*(human_baseline/actions)^2)`，最后受已完成非零关卡的权重上限裁剪。24 个 game-run 按原始动作数独立重算，与 final_score 逐项误差均小于 1e−9。平均分差也可精确记账为：新完成关卡的未裁剪权重贡献 +10.468640、丢失关卡 −5.699851、两臂共同完成关卡的效率变化 −0.083832，以及最终上限裁剪修正 −0.798601。简单地用“净多 3 关”无法解释分数大小。

archive ledger 中有实际 query 的游戏为 tn36、sp80、bp35、lf52；它们对全池均值贡献 +2.267557，净多 2 关。零 query 的另外 8 游戏贡献 +1.618799，净多 1 关。最大上升 m0r0 与最大下降 ft09 都没有查询；sp80 有 20 次旧动作命中却没有分数/关卡增长，lf52 有 3 次命中却退关。查询分组来自实际轨迹，是事后记账：零 query 游戏仍接收新 API 说明并参与同一共享调度，不能将这两个分组当成随机的“有检索/无检索”对照。命中也不自动等于模型看见了有效区域或采用了正确机制。
