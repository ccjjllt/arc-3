# 034 v9：类型明确、状态敏感的执行接口

2026-10-24。v8四份源码已通过提取，但三份实际弃权、一份准备点击错误背景；两题均无新增关卡、同期分数差0，host动作仍0。本版只修运行接口与反馈的可用性，不宣称只修接口就能提高分数。

## 一个主改动

明确`frame.ascii`是字符串，用通用示例`rows = frame.ascii.splitlines(); observed = rows[row][col]`读取像素。字符严格区分大小写；色码本身不证明目标／棋子角色。不提供具体游戏的目标颜色、坐标、规则或后验解法，也不改变原生Frame属性或对象表示。

按计划状态验收：合法abstain无动作时可以没有证据／替换绑定，返回普通主循环，不因强制填空消耗唯一反馈。goal／reason、strictJSON和资源边界保留；若提供证据或绑定仍逐项检查。ready与completed不放宽原有证据、绑定和动作限制；预测的对象／目标并集完整覆盖和实际动作绑定仍严格。

原生求值的实际returned_plan写入事件，并在计划验收失败的唯一反馈中保留一份；同次汇总有界计划错误，尤其同时发现重复坐标和错误颜色。不自动去重，不替模型改目标、颜色或计划，也不从候选吞掉的异常推断成功。合法弃权只是停止，不能称有效行动、局部规则修复或过关。

## 核验与原预算

先以原样保存的v8实际输出作纯验证回归：三份abstain应正常停止，su15首次ready仍应因重复／六个错色被拒收；这不能制造新的真实动作。沿用窄原生CPU checker，覆盖空弃权不重试／不消费共享额度、错误ready多诊断回传实际值、模型自行修订后能执行、completed空证据仍拒收，以及原回滚／预算／真实mismatch共用一次反馈。

冻结后仍运行原两切点B→A：450秒／60动作、每臂600秒、单请求60秒、辅助总120秒包含在450内，启动4200秒、总会话7200秒。模型、thinkingFalse、对象目录、旧假设、主循环和触发不改。完整源码和实际返回值均受原16384输入token检查，超限停止而非悄悄裁掉证据。

## 明确停损与正式提交条件

若这次修正后两个切点仍为0 host动作，停止独立程序分支的合同调参，不继续放宽ready／预测门槛；随后回到普通主循环或辅助推理配置的独立假设。thinkingFalse的净收益尚未证实，但本轮不同时改它。

实际动作也只是必要条件。只有程序改变错误行为并产生可解释推进，才进入完整25题同期同预算比较；完整净收益后做真实GPU保存版本和准确版本的正式submission。官方超过009 v2的31.16才算提分成功。本次仅私有机制诊断。
