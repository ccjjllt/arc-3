# 034 v6：当前对象几何与真实变化证据

2026-10-24。v5已有完整交付、真实动作、2次局部预测命中和反例修订，但两题同期均分下降14.7535。下一版只检验一项表示设计：让辅助程序直接使用当前连通区域几何与近期真实变化，避免重新写错误的对象提取器。009 v2／31.16继续保留。

## 干预范围

- 同一个纯函数从当前ASCII生成同色4连通区域：逐帧ID、颜色、像素数、边界框和可精确展开的完整形状；同色不同实例分开，不把所有同色像素取一个bbox。
- 最近最多2次公开真实转移提供动作坐标和区域变化的几何关联。只报告同坐标观察，不推断因果或跨帧对象身份；跨关／形状变化只作边界记录，不能证明新关对象角色。
- 几何目录进入辅助事实包，并由原生sandbox的`frame.object_evidence`按每次当前帧重算。模型不必再手写连通分量解析。使用说明要求在goal中交代选中实例、角色假设与实际支持，预测覆盖所声称对象的相关完整范围。
- 连通区域不是语义对象，角色仍由模型判断。静止不等于UI，UI控件也可能需要交互；没有游戏名、颜色、固定坐标黑名单或宿主正确规则。

本轮检验“可直接消费的对象几何及其使用说明”整体效果，不分别归因每个字段。宿主合同不新加语义真伪裁决，不强制把4连通区域当完整对象，不增加模型轮次或零动作异常重试；thinking、输出上限、主循环和触发条件保持v5。

## 判别顺序

离线先验证几何精确覆盖、同色分离、单像素、非矩形、跨关不作动作支持，以及host／原生sandbox计算一致、动作后确实刷新；只用切点前事实和已保存反例，零真实模型调用。

在线仍用ft09 cut27／su15 cut86，B→A，模型与原冻结前缀不变。每游戏450秒／60动作，辅助单请求60秒、累计120秒计入450秒，短合同最多3动作，最多一次真实mismatch修订；每臂600秒，模型启动4200秒上限，总会话7200秒。不足完整预算就中止，不缩后臂。

必须分别报告：目录是否被程序使用、对象范围和角色是否有真实支持、预测覆盖／失配原因、反例后是否纠正对象选择，以及实际新增关和得分。代码使用了目录、少点一次UI或预测命中本身都不足以进入完整题池。

若仍出现对象错误或无净推进，停止本版扩大，依据实际代码区分表示不足、规则探测不足和局部目标未连接求解。只有出现可解释的任务推进且同预算对照有价值，才冻结候选做完整25题同期比较；正式成绩超过31.16才算提分。
