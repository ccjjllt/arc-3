## 2. 新论文：停止汇报后继续，究竟改变了什么

[Improving Environment-Agnostic Coding Agents: The Role of Scaffolding](https://arxiv.org/html/2610.22289v1) 的 Table 1、§4/7/8/9 比较同一代理仅改变一段指令：困难或不确定时提前返回，由控制器自动继续。每条件 **3 遍×25 public games**，无跨游戏文件；每关 1,500 动作上限，ARC 运行**没有额外硬墙钟或 token 上限**，与本项目 9 小时共享 GPU 不同。

| 模型 / effort | 原版 RHAE→stop-and-report | 差值 | cost tokens（百万） | 成本变化（由表值计算） |
|---|---:|---:|---:|---:|
| GPT-5.5 high | 27.57→34.86 | +7.29 | 9.36→14.19 | +51.6% |
| GPT-5.5 xhigh | 50.45→52.36 | +1.91 | 16.08→20.18 | +25.5% |
| GPT-5.6-sol xhigh | 70.81→77.33 | +6.52 | 16.30→16.57 | +1.7% |
| GPT-5.6-sol max | 89.59→90.96 | +1.37 | 15.34→18.01 | +17.4% |

这些是跨三遍均值，重复编号不是共享随机种子；方向不保证逐遍一致。成本是输入/缓存/输出加权代理，不是本地解码量或 GPU 秒。作者明确未分离流程改善和更多/不同分配的推理。较弱条件增益最大，却也多花约一半成本，不能移植成“短提示免费加 7 分”。[论文 Table 1、§7.2、§9.2](https://arxiv.org/html/2610.22289v1#S8.SS1)

### 作者代码的独立静态核对

通过 GitHub 读取并固定 commit `0d9203287a9a9651b6b3501b7907a0191786a4c9`。baseline 与 stop 目录各 15 个文件的 Git blob 比较，**只有 `continuation_string.txt` 不同**；`agent.py`、runner 等相同。选定控制源码、MIT 许可与映射已保存于 [envtraverse](frontier/2026-10-18/envtraverse/source-manifest.json)。没有执行这些文件；当前源码与论文说明一致，但未恢复全部论文运行的源码 hash。

- `agent.py:225–245` 检查环境步数：普通返回后继续；连续一次 continuation 未动作则附无动作提醒；提醒后仍未动作则退出这一控制循环。**这是新模型推理机会**，不是 CPU 函数一调用就无成本纠错，也不是每真实动作额外调用一个 critic。[agent.py](https://github.com/astroseger/envtraverse/blob/0d9203287a9a9651b6b3501b7907a0191786a4c9/envtraverse_v0.1/src/agents/agent_v1_01_wstop/agent/agent.py#L213)

- 外层 `agent_runner.py` 还会在退出或日志停滞时恢复，只要环境未终止、已有 session，最多 10 次。当前归档源码的日志无活动阈值是 **2 小时**，不能套用旧 2607.15439 的 30 分钟。这个 watchdog 看日志活动，不等于发现游戏长期不进展。[恢复监督源码](https://github.com/astroseger/envtraverse/blob/0d9203287a9a9651b6b3501b7907a0191786a4c9/envtraverse_v0.1/src/agents/agent_v1_01_wstop/agent/agent_runner.py#L19)

**与本项目的重叠是限制，不是新贡献。** 当前 [ToolAgent `_analyze_tool_turn`](runtime-bundle/src/ARC3-Inference/inference/agent/tool_agent.py:6910) 已在无 tool calls 时保存 assistant 内容/推理、附调查提示、继续循环。Franzen 也已有死亡自动 RESET。论文的 Controlled_RESET 不能再算我们的新增功能；“支持暂停再继续”也不必从零实现。若自然无工具返回已被相同方式续接，可能只剩恢复提示是否指向有效证据的差异，不能把底座原有控制收益写成候选预期。

**最小可测版本（本项目推论）**：先从已有日志定位多个“模型自然无工具返回→原提示继续→继续无动作或重复同一失败解释”的窗口；只替换该窗口的恢复文字，要求明确当前不确定点、检查已有证据中的矛盾、选一个能区分解释的下一步。保留会话、函数、动作结果与调度，不新增全局汇报协议，不清空上下文、不额外插入独立反思轮。原版相同事件照常用原恢复提示，预算完全一致。若窗口稀少、下一段只是复述或已经有有效新探测，停止这个候选。

## 3. 可执行模型与验证：有支持，但不是轻工具必然有效

[Rodionov 2607.15439v2](https://arxiv.org/html/2607.15439v2) 的 25-public、每条件单遍嵌套比较中，完整 verification 处理各设置最高；但同时提供固定接口、模板、回放工具，并增加成本。例：GPT-5.5 high，textual/verification **58.85/65.64**，cost tokens **63.17M/205.10M**；xhigh **72.51/74.78**，成本 **68.16M/222.06M**。只要求维护 executable 在两项 GPT-5.5 条件均低于 textual。`plan_executor.py` 能预测后逐步执行、失配停批，但提示未要求使用，也没有报告其独立消融。因此这不能证明给本项目增加 `act_checked` 就会涨分。[§3–6、Tables 2/3](https://arxiv.org/html/2607.15439v2#S6)

[Tycho](https://arxiv.org/html/2607.28287v1) 提供更直接的反证：Opus 4.8、同一公开池，按失配自动建模的 trigger 预测匹配 **88.1%**，却只有 **83.07/162 关**；让 actor 选择 builder 的 orchestrator 预测匹配 **16.2%**，得 **88.49/166 关**。trigger 的 builder 调用 **1,192 vs147**；全部策略上限为 3,500 LM calls、$750/game。它证明调用时机与使用方式重要，没有分离单次反例反馈的净效果；低预算曲线是历史前缀，不是低预算重跑。[Tables 2/7/8、§7](https://arxiv.org/html/2607.28287v1#S7)

[When a Verified World Model Still Loses v2](https://arxiv.org/html/2607.14169v2) 在构造棋类中，以匹配搜索预算和 20 seeds/4,800 局，展示“采样转移全对、搜索分布状态≥98%正确，仍因罕见关键规则输掉游戏”；更多例子没有稳定恢复遗漏规则。这是**非 ARC-AGI-3** 的机制反例，不能移植其效应量，但支持将“错误是否落在关键目标/终局”与总体像素准确率分开。[§3–5、§8](https://arxiv.org/html/2607.14169v2)

### `check_sim/act_checked` 应回答的具体问题

本项目已有 [Sujan 静态审计](013-notebook-update.md)，不是该工具独立收益证明。当前候选至少需要区分三件事：

1. **发现错误**：预测必须在真实动作前产生；完整 action（含点击坐标）、观察身份、预计比较区域/对象及预期状态绑定在一起。动作后发现差异，不能在后帧已见后回填预测。
2. **停止坏计划**：只有同一计划尚有后续动作时，首个有关失配才可能节省后缀。空预测、未执行模拟器、纯 HUD 变化和关键对象预测错误应分开，不能合称“验证通过/失败”。
3. **修正模型并改变行为**：返回差异后，模型须实际撤回一个规则/目标或修改对应函数，随后在新证据下正确应用。只打印 mismatch、换函数名、增加例外直到历史拟合，不算研究链完成。

[Kepler](https://arxiv.org/html/2610.00834v1#S2.SS2) 的代码合同正好提醒这一边界：有效预测失配才中断剩余计划；模拟异常或零覆盖仍可警告后执行。其 100/95.97 是公开游戏最终回放段，不能拿来证明首次探索的效率或单工具因果增益。项目页仍留有比论文更强的“每步均验证”及旧 cutoff 说法，本轮采用论文明确披露的条件语义，不将主页口号当机制保证。

**最小实验建议（推论）**：仅在模型本来就写出模拟/搜索并要执行多步计划的自然病例，加入一个有界的预测比较入口；不要求所有动作先建模，不强制遍历全部历史。初筛记录“自然计划→动作前预测→有关失配→少走错误后缀→下一次规则修订/新探测”，同时记录未覆盖动作与 CPU/生成成本。如果没有自然预测采用，或大量误停来自表示差异，立即停止；不要用人工固定调用前缀来制造采用。003/012 已说明依赖新自报/API 的假说可能根本没有被实际检验。

## 4. OPINE-World v3：更有价值的新证据在探索选择

[OPINE-World v3](https://arxiv.org/html/2607.01531v3) 新增的 25-public 配对探索层消融为 **78.40→58.16、160→126 关、20→12 全通**（移除探索层）。模型均为 Opus 4.8 high、1M context，最多 2,000 actions/game 或每关停滞>500 动作；400 动作比较中 full/no-layer/ε-greedy 为 **65.97/52.96/39.49**。同证据建模和修订另有 g50t 多重复研究；这些不构成隐藏泛化或单因素短提示消融。单环境可用到 20 亿累计 tokens，全池 synthesis 合计 174 小时。旧 v1 的“没有组件消融”须更新，但新证据仍远离本项目算力条件。[§4–5、Appendix C/F](https://arxiv.org/html/2607.01531v3#S4)

可迁移的核心是：当前模型解释不了的效果，也许缺了对象属性、关系或历史阶段；重新排列已经熟悉的对象不一定能发现遗漏机制。**这是本项目的研究假设，不是将 Bayesian 框架缩成一句话就能获得论文收益。** 宿主只用实际观察/动作/结果，不能预设颜色是玩家、组件是对象或默认裁掉边界；008、tn36/lf52 的病例已表明表示与暂态可能本身有错。

最窄的试验可与上一节预测入口分开：在已确认的停滞窗口，恢复提示促使模型提出两个仍符合历史的解释，选择一个现有合法动作来区分它们，并在返回后明确哪一个受反证。这里无需新的保存 API，也不预设要先写完整 simulator。最重要的采用证据是**一个原本未测试、与目标有关的交互真的被执行并改变后续规则/行动**，而不是输出了两个假设名称。重复失败动作减少、获得新信息、关卡推进和推理成本分别记录；不要用随机“多探索”替代选择性探测。

## 5. 四种候选的证据强度与停止条件

“较强”仅指相关机制的研究依据，均不等于已经在 Qwen3.8-Flash-Next 上验证。

| 可迁移机制 | 证据强度与项目关联 | 最小验证 | 主要失败/停止条件 |
|---|---|---|---|
| 自然返回后的短恢复提示 | 中等：新论文三遍均值正，但成本增加；本地控制逻辑已有重叠 | 先证实多个原版 no-tool 恢复失败窗口；只换此处提示，等墙钟 | 无可作用窗口；更多空转/复述；打断有效 CPU 推理；只靠额外生成获益 |
| 针对遗漏交互的区分性探测 | 中等偏强：OPINE v3 有全池配对探索消融，框架与预算不匹配；对应005/006目标猜测与无效探测 | 选不同游戏的自然停滞机会，观察实际探测→假设改变→行为/关卡 | 只是随机探索；探测与目标无关；被错误对象分割误导；反证后仍原假说 |
| 已有计划的局部预测校验 | 中等：有实现和组合系统证据，Tycho有明确反例；对应自然simulate/BFS | 一个计划前缀、有界CPU、同动作绑定；记录真正避免的坏后缀 | 新API不用；零预测；比较器误停；修模成本超过节省；预测准却不懂目标 |
| 证据驱动的局部程序修订 | 中等：Memento与OPINE支持可修订假说，直接低预算独立收益仍弱；承接007/015程序连续性 | 已有函数的真实矛盾→定位一处规则→修改→再验/行动 | 整个模型重写；为拟合历史堆例外；旧常量跨关污染；只数代码变化而无行为改善 |

[Memento 3](https://arxiv.org/html/2610.11794v1) 的规则册/程序修订是相关设计证据：Opus 5、公开25/183满分；规则册消融仅3游戏且双方满分，未给本项目可匹配预算。本轮未找到可核验的作者完整实现。它支持保留“为什么修”的证据链，不能据此立刻启用底座关闭的全局结构化记忆。

[Tracing](https://arxiv.org/html/2610.11450v1) 的文件轨迹研究提醒跨关硬编码可造成负迁移；不是扩大持久变量的因果实验。015 当前结果报告只确认提交/恢复机制发生，尚无两个游戏的确凿自然消费链；其 +11.46 不能当候选采用已通过。最终采用结论应以完整原请求复核为准，而非 AST 同名计数。[015 分析](015-results-analysis.md:13)

## 6. 对 restart 的结论及预算约束

必须区分四种东西：同会话返回后继续、技术崩溃恢复、丢弃上下文重新推理、真实环境 RESET。新论文主要支持第一种；作者旧实现含第二种。它们不是 Heliosli 的长停滞上下文重启的干净对照。

[NVIDIA AVO 官方说明](https://developer.nvidia.com/blog/nvidia-avo-reaches-100-on-arc-agi-3-demonstrating-a-frontier-level-general-purpose-architecture-for-long-horizon-autonomous-agents/) 描述 supervisor 可在停滞时重定向策略；公开25全通是系统结果，未给 ARC 的“仅restart开/关”消融。7天GPU kernel工作的监督经验不等于 ARC 算力预算。没有查到能证明固定 96k 清空对本项目模型有效的匹配研究。

因此先保留短恢复/区分性探测作为可比较的轻候选，**不建议先实现按 token 阈值清空上下文**。需要清空的证据应是错误先验持续污染，而不是仅无动作、token多或排队久；005 中长无动作也有成功规划，014 中恢复调度后的 sc25 仍能推进。清空会损失正确证据和缓存，产生额外生成，必须单独付账。

截至016的本地教训仍适用：CPU合同通过、机制触发、模型采用、决策改变、净覆盖和隐藏得分是六件不同的事。014尾调度均分小涨但覆盖下降；015短池均分明显涨但采用证据不足；016本轮确认完成，47.1340→47.4634、105→111关、覆盖+0.2136，但去掉最大正项r11l后其余均差−1.5205，未过预设晋升门。[016结果分析](016-results-analysis.md) 不能预言原生值或后续调度的效应量，也不能把几个未经确认的小改动相加预估金牌差距。

本轮团队实时配额核对还显示两个账号当前总额度均为6h且已用超额，旧记录的30h不能继续当作可用资源。本文的短采用与全池A/B是有资源后的条件方案；先完成现有轨迹审计与候选冻结，不承诺按旧余额立即启动GPU。实际资源与启动决定以同期综合研究决策为准。

后续优先级应由本地机会审计决定：**若 no-tool 恢复窗口丰富，先测特定恢复文字；若已有自然预测/坏计划证据更强，先测局部校验；若模型在熟悉动作中循环却漏测关键对象，先测区分性探测。** 每轮只变一项，短采用筛选后再固定全池等墙钟 A/B。所有额外模型回合、CPU耗时、缓存变化、动作数及每游戏资源都纳入；不能用论文API加权成本换算本地GPU收益。
