## 已完成实现

新增 `bounded_executable_plan.py`，复用原 034 的程序验收与逐动作执行器。自然臂、同状态诊断和正式保存使用同一 `DEFAULT_CONFIG`：4096 输出 tokens，32,000 字符及 64,000 字节请求上限，最多 1600 字符的未验证假设，单请求 60 秒，共享额外预算 120 秒，剩余不足 180 秒不启动。

新请求仅含完整暂停代码、相关函数依赖、当前完整帧和必要近期证据。请求级关闭 thinking/preserve_thinking，并要求单个 Python 工具交付；普通主循环保持原设置。必需代码超限时请求前回退，不裁切函数或棋盘。补充 finish_reason、实际请求是否发生、失败阶段、上下文 hash、耗时与预测覆盖日志。

审阅发现并修正了两处具体问题：诊断 fork 的引擎动作名先通过与合同相同的归一化接口，再发布 `MOUSE` 等模型动作名；新错误字段只进入 036 的返回，不改变原 034 主循环看到的拒绝对象。独立审阅结束时没有新增未修复的 P0/P1 阻断，但真实模板的 required-tool 兼容仍待 GPU 验证。

正式构建器 `build_036_submission.py` 复用未修改的 009 构建器，安装同一候选。额外明确采用第一 cell 总时钟，将冷加载和求解纳入 32400 秒上限，预留 300 秒收尾；保存验证使用 4200 秒启动上限、5400 秒总上限和原有 300 秒真实两题求解。这些运行差异已经明示，不能被归因为程序修订的算法收益。
