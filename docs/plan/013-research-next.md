# 013 研究更新与下一实验方案

日期：2026-10-17。承接012采用失败，服务于终局金牌及前五奖金。综合结论见[研究决策](../../research/013-research-decision.md)。本轮完成研究和CPU证据；下一GPU实验尚未实现或启动。

## 首选实验 80k tail 单开关

固定沿用[005配置](../../experiments/005-full-baseline.json)的25个完整游戏ID及顺序，每臂1 pass、7254秒、10活跃流、warmup0，baseline→tail。研究OFFLINE、同一模型加载、独立CPU进程、组间cache flush。候选只将ARC3_PRIORITY_TAIL_LOOKUP由remaining改为1；PACE继续0，003/006/007/010/012关闭。两臂相同被动诊断。

实现前需完成三件可审查的工作：

1. 扩展显式实验配置/runner支持单开关环境覆盖，并记录最终生效值；不改正式009。构建新Notebook和源码hash，真实IPython写出/patch检查沿用现有合同。
2. 在实际enqueue/reprice/selection处保存只读priority/snapshot、候选队列和单调时钟。现有计时器只记录等待区间，不能把013近似CPU重排当精确队列回放。记录有界、失败不影响调度。
3. 独立验证并修复012的handover后迟到新请求问题；若纳入运行则两臂共同采用。使用CPU人工deadline/等待反馈验证截止前行为与取消路径；不把修复算成tail独有收益。

预计4.3h，计划硬限18000秒、启动上限1200秒、预留收尾。若启动超支，宁可判定不符合冻结预算而停止，不把缩短后的实验和7254秒配置混报。准备阶段及上传前核查共享余额/实际Kaggle配额；研究规划不等同独占30h。

## 衡量和晋升

每臂保留25局原始benchmark、逐关动作、实际scorecard、analyzer与动作账token、实际snapshot/选择、首次准入、prefill/cache字段（无法取得时标缺失）、CPU/墙钟/GPU采样、退出和截止后行为。独立复算每游戏及全池AE，同时报告完成关卡、按游戏归一化的完成权重、全通数与逐游戏差异。

首轮负向、覆盖回退、分配几乎不变或正差依赖单一游戏时，不晋升，不追加同版盲跑。首轮均分和加权完成覆盖为正、完成总关卡不降且至少两个游戏有新增关卡时，才安排倒序确认；这是研究选择阈值，不是统计显著性证明。所有预设25局保留，不删除回退项或未使用新机制的游戏。

确认轮tail→baseline，同样预算和相同代码/诊断。两轮都正向且机制/资源解释成立才进入正式候选准备。若方向反转，冻结为未获支持；不能仅用两轮平均正差晋升。逐游戏留一敏感性作为描述，不用于事后排除游戏。

## 原生计算值的并行准备

仅实现成功无动作snippet的有限普通值跨调用；会话和当前观察严格绑定，动作/RESET/过关失效。保持原函数保留合同，不保存闭包/函数对象/模块，不把snapshot绑定到动作后残留旧数据。类型需覆盖list/tuple及有界set/dict tuple keys，并保持精确语义；拒绝自定义对象协议、循环、超限、非有限浮点。

人工CPU验证数据合同和原SDK动作保真后，再做≤1h采用试验。固定ft09/re86/bp35和ar25控制，baseline/候选同短预算，模型自然生成代码；不执行日志里的旧计划、不注入未来状态/答案、不强迫put/get。至少两个游戏出现跨snippet自动恢复并实际使用，且正确性/陈旧值/额外开销可审查，才准备新全池A/B。4游戏短测不能用来宣称提分或隐藏泛化。
