# 017 本地机制证据：先保护观察到程序的保真

日期：2026-10-18，Asia/Shanghai。结论：**当前最强可操作证据是观察数据在裁剪、栅格化、硬编码时失真，导致正确规则被错误拒绝；优先研究轻量观测保真约束，比继续加记忆 API 或全局 stop-and-report 提示更有直接依据。** 这是一项候选排序，不是已验证提分结论。

本轮只读审计 015 的 8 份完整请求和 016 的 5 游戏×2 臂请求；只从运行日志、已保存帧相关输出及当前框架代码取证，没有读取游戏机制源码、执行模型生成代码、启动 GPU/模型或正式提交。派生证据由 [analyze_016_results.py](../../../scripts/analysis/analyze_016_results.py) 生成至 [016-analysis](../../../experiments/016-analysis/)。

## 2. 015：涨分不等于原生值产生因果收益

### 2.1 ft09 的直接错误链：用外接框填色，再把错图案硬编码

原始：[baseline ft09](../../../runs/015-native-adoption/baseline/ft09-0d8bbf25_p0_requests.jsonl)、[native ft09](../../../runs/015-native-adoption/native_values/ft09-0d8bbf25_p0_requests.jsonl)。下面行号均指原始 JSONL。

- baseline **19/21 行**：对每个分割节点取 boundary 极值，再把整个矩形 `pieces[(r,c)]=color`。非矩形连通组件由此被错误实心化，不能由节点的 bounding box 得到内部逐像素颜色。
- **29 行**已经打印精确 6×6 ASCII 小裁剪，关键图案的中间两行是 `WWOOgg`。正确 3×3 为 `gWg / WOg / WWW`。
- **41 行**又在 Python 字面量 `L[(5,2)]` 中写成 `gWg / WOW / WWW`，恰好一个 subcell 灰 `g` 误为白 `W`。CPU 只解析该字面量和此前打印的 crop，独立复核差异为 `(1,2): W→g`，无需执行任何模型代码。
- 此错误使普通格 `(5,3)` 被错误涂成橙色；模型把“未过关”归因于目标映射规则，尝试反色、D4、偏移、其它候选。**67 行**才用 `current_frame.ascii` 逐样本重建 key；**69 行**明确更正目标，13 次补点击后第 3 关完成。
- native 对照的 **19 行**直接看四个精确 ASCII 小裁剪；**21 行**用正确的 14 个目标点过第 3 关。全段没有读取前一个 snippet 定义的普通变量，targets 在当前 snippet 内重建。

| ft09 第 3 关 | baseline | native |
|---|---:|---:|
| 本关动作数 | 91 | 14 |
| 本关 action-attached tokens | 86967 | 3652 |
| 从游戏开始至该关完成 | 963.13 秒 | 78.05 秒 |

baseline 第 3 关耗尽绝大部分短预算；native 第 4 关在 252.81 秒完成，随后停在第 5 关。差异可具体定位为观测提取/转抄路径与后续假设检验；不能称这 77 动作、83315 tokens 全是候选可避免成本，更不能从一个短预算轨迹预测 LB 提分。

**真实 NameError 机会也存在，但不是这轮涨分归因：** baseline **41→43 行**同一 request action=52，前段无动作、成功定义 `L/cells/names`，后段 `L.items()` 报 NameError；**45 行**模型重新从 ASCII 构造并继续。原生值可能修这条丢值路径，但 native 实际已经走另一条提取路径，未重现或修复此调用链。不能拿 baseline 的可修上限替代候选的真实采用。

复核：[representation-proofs.json](../../../experiments/016-analysis/representation-proofs.json)、[015-level-timing.json](../../../experiments/016-analysis/015-level-timing.json)。

## 3. 016：tr87 提取器错位制造了假反证

原始：[pace tr87](../../../runs/016-pace-allocation-jiyujia/pace_1x/tr87-cd924810_p0_requests.jsonl)。候选最终 4/6，baseline 6/6；候选实际拿到更多 slot 与 tokens，不能仅归因分配不足。

- **65 行起**进入第 5 关。字形裁剪将 tile top 当作 ink top，取了空白首行、漏掉最末墨迹行；字形规范化随后把这种错误 mask 当真实符号。
- **81/87 行**模型枚举两个轮盘、计算与候选分词的交集，得到 `C_S cycle size 7 hit False / B_P cycle size 7 hit False / surviving permutations: []`；这是把错误表征上的不一致误当“规则已被排除”。
- **85 行**打印底部实际像素，首个 5×5 黑色字形是 `##.## / .#.#. / .###. / .#.#. / ##.##`，15 个黑色像素；**97 行**打印现有提取结果是 `..... / ##.## / .#.#. / .###. / .#.#.`，11 个像素。独立 CPU 字面量比较验证：它恰好是空白顶行加真字形前四行，漏 4 个黑点。
- **101 行**模型自认找到截断问题，写 `bg2(..., r_top+1, ...)`，但同时 `SLOTS['A_S']=(11,...)` 已经给了墨迹首行 11。最终实际采样 12..16，而此前 segmentation 打印墨迹为 11..15；底部同理，参数 44 再加 1 得 45..49，而真实墨迹 44..48。**“已修复”文字不是修复成功证据。**
- **105 行**再次花 8 动作枚举轮盘，输出 `HITS []`，最后仍没有完成第 5 关。不能断言正确裁剪必能解此关，因为规则假设还需验证，但当前假反证已经有逐像素可复核根因。

量化暴露：第 5 关从 request action=133 到 221 已消耗 88 次后续动作；其中部分用于真实交互探索，不能全部算错裁剪带来的浪费。明确的两次轮盘检查是至少 7+7 次 UP，修复声称后的重复枚举再 7 次 UP（另有移动 cursor）。这些仅是机会量，不是预计可挽回行动数。

这与 ft09 不同机制层面的同类错误：一个把外接框当形状、一个把 tile 坐标和 ink 坐标混用。共同点是**程序输入未经独立核对，后面的精确搜索会精确地求解错误问题**。

## 4. 真实预测→失配→修程序：有机会，也已有自然采用

### m0r0：已有预测但循环未停，后来真正停止并修模

原始：[baseline m0r0](../../../runs/016-pace-allocation-jiyujia/baseline/m0r0-492f87ba_p0_requests.jsonl)。

- **37 行**18 动作执行循环把 `pred==act` 写入 log，但只在 terminal 时 break。第 2 动作 RIGHT 已预测右块到 `(44,44)`、实际到 `(44,34)`；整段仍继续余下 **16 动作**，总计 **8 次** `pred==act=False`。这是明确“检测存在、决策没变”的缺口；16 只是停批能阻止的后续动作上界，不能当净节约。
- **39 行**模型根据失配改成右侧水平镜像控制，并用一次 RIGHT 验证实际两块朝相反方向移动；这是真实修模，不是新 API 缺失。
- **79 行**第 2 关已有 stop-on-mismatch 循环。第 12 动作预测继续到 `(8,3)/(7,9)`，实际回到初始 `(1,4)/(1,8)`，循环停下；**81 行**查原始 history，发现没有 game_over 却发生重置；**85/89 行**把危险格从“阻挡”改成 DEAD 转移、重跑搜索，后续 19 动作与模型匹配。

因此小型停批契约有机会，但大而新的验证 API 会重复基线已有能力。若研究该方向，应只补“显式比较失败必须退出当前动作序列，先查表征/终态，再更新模型”的断点，且检查是否真实被采用。

### r11l：强校验也会因为观察提取器错而假报警

原始：[baseline r11l](../../../runs/016-pace-allocation-jiyujia/baseline/r11l-495a7899_p0_requests.jsonl)。

- **89 行**已自然实现逐动作 `run2`：检查可点击区域、执行、比较 M 点，失配返回；**91 行**第二次点击即 `verify_fail`，后 6 个计划点击没执行。
- **105 行**升级 `live3` 把每个中心色像素候选当一个物体中心，输出 7 个 diamond 候选而本应 5 个；M 点却正确。模型认为这是假报警，**107 行**打印精确小裁剪后确认相邻颜色覆盖导致多个候选中心，转回较弱 M 检查。
- **111 行**一个真实跨关产生新 board，M 当然不同；runner 先比 M 再检查 `level_completed`，将正常跨关写成 `verify_fail`。后续 **113 行**已经是第 3 关。终态判定必须先于“仍在同一观察世界”的一致性比较。

可迁移的是校验次序和提取器的可信边界，不能简单设“所有 mismatch 都回退/RESET”。盲目强化校验可能增加假停与成本。

## 5. stop-and-report / 无工具调用的反证

016 选取的 867 个 Python 调用旁，只有 6 个独立无工具调用 assistant：

| 文件/原始行 | finish_reason | completion tokens | 内容性质 |
|---|---|---:|---|
| baseline r11l:147 | stop | 31 | “把常量内联后继续写函数”，无最终报告 |
| pace r11l:47、101、149、151 | length | 各 12288 | 推理或计划中途达到输出上限 |
| pace tr87:83 | length | 12288 | 规则分析中途达到输出上限 |

自然 stop 的 r11l 触发一次 `You have not acted yet` 恢复提示；它后来重复出现在 48 个历史快照中，**不是 48 次触发**。5 次 length 合计 61440 completion tokens，占这 10 个选取会话 analyzer tokens（1721511）的 3.57%；这些是输出截断，不是模型主动发报告后忘记行动。015 四次无工具调用也都是 length。

因此本批证据不支持把“自然报告型早停”定为主要瓶颈，也不支持加入每轮全局反思/汇报。长推理中途截断可以列为独立候选，但调整 max_tokens/恢复策略会改成本与搜索路径，需要新的单因素证据；不能由当前比例承诺收益。

## 6. 下一实验排序、验收与反证

**第一候选：观测到程序状态的保真约束，使用现有工具，不新增 API/缓存/游戏特例。**

建议最小提示/流程仅针对构造 mask/矩阵/符号字典时：

1. 从指定小矩形的原始 ASCII 单元构建，明确坐标是含端点还是半开区间；避免先在自然语言转抄。
2. boundary/bbox 仅是范围，不能无条件当填充区域；对声称代表某个分割节点的同色 mask，用像素数和几个边界/内部样本校核。多色对象、遮挡、marker 洞与 disconnected components 必须显式保留语义不确定性。
3. 用程序输出小 crop 与派生 mask 的并列证据，确认恢复出的 footprint 与原观察一致，再进行 D4/搜索/全局假设排除；失配先检验提取器，再否定规则。

**CPU 门：**使用本报告已保存原始数据，不调用引擎即可复现 ft09 的 1 subcell 错误、tr87 的 15→11 像素错位；实现方还应拿正常非矩形、多色/空洞、断开对象作反例，防止为了通过这两例变成无条件填洞或只取最大组件。当前脚本已完成前两例的解析复核，未实现任何运行时干预。

**自然采用门：**先做小预算、至少两种非同游戏的运行时观察→构造→独立核对链；必须看到错误被实际发现并纠正、或正确提取被确认后影响计划，同时记录 token/CPU/动作开销。仅多打印 crop、仅调用 helper、仅最终分数上涨均不算。两游戏仅验证采用，不替代全池收益对照。筛选游戏若取自本次诊断必须明确为已知诊断池，不能冒充 holdout。

**否定条件：**模型本来就精确采样且约束没有改变决策；约束把正确多色/孔洞对象错误归一化；在校验上耗时却未恢复动作；两游戏无自然采用；或者全池总覆盖/关卡下降。ft09 native 本轮已经做到了正确 crop，说明提示不一定是必要条件；必须验证新增约束有边际作用。

**第二候选：已有预测比较的失配停批与先终态检查。** 先审计大量现有 `pred/act` 循环中“比较了却不break”的普遍性，不应只凭 m0r0 一例开发复杂新 API。r11l 的假报警是必须防止的反例。

**暂缓：**继续 native 值全池扩跑；泛化填洞/整套对象语言替换；全局 stop-and-report 提示；tail/pace/记忆叠加。每一条都需要自己的采用证据与同成本对照。

所有机会数都是已发生轨迹上的暴露或静态可修范围，不是分数增益。即使诊断池修好某关，也不能把其加权贡献直接映射为隐藏 110 游戏或正式排行榜的金牌差距。
