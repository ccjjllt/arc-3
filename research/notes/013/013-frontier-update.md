# 013 — 前沿复核：从增加工具转向完成可验证的推理链

访问日期：2026-10-17，Asia/Shanghai。本文重新读取一手论文、作者仓库和官方评测；没有运行第三方 agent、调用模型、启动 GPU 或安装依赖。使用场景是本项目的离线 Qwen3.8-Flash-Next、单 RTX PRO 6000、全局 9 小时、110 个隐藏游戏；赛制和模型许可由本轮竞赛调查单独核对。公开开发集成绩只作为机制证据。

## 结论

**本轮最重要的新证据是 Memento 3 的规则修订流程、PRO-LONG 的 10/12 v3，以及 Gemini 4 Argon 的官方半私有结果。它们没有证明“再加一个记忆 API”能提高本项目成绩。**

近期值得试的是：让模型已经自然写出的计算、程序和假设，在之后的决策里被正确接续；在需要搜索的局部问题上，让一个有界 CPU 计算替代重复语言推理。完整世界模型、多模型人口、全历史逐像素强制验证属于高上限路线，当前缺少本地模型和比赛预算下的证据。

010→011 的动画收益未复现、012 的 get=0，要求我们改变筛选方式：一个候选必须先出现真实的“证据→使用→决策改变”链，才值得完整得分实验。不能因某前沿系统满分而跳过本地采用验证，也不能用一次成功调用宣称已经找到提分办法。

## 新资料与旧结论的变化

### Memento 3：新增，应研究规则修订，不应整套照搬

论文当前为 [2610.11794v1](https://arxiv.org/html/2610.11794v1)，2026-10-08，§3–4。Opus 5 extra-high + Claude Code，25 public、183 关、100 RHAE、7,518 动作。规则册与程序共同维护，反例可撤回规则，代码需通过全部已观察轨迹逐格回放；模型权重不更新。三游戏去规则册消融两边都满分：动作 617/677、agent turns 678/830。人口扩展只测试 wa30：N=1/2 为 899/597 动作、两边满分。未给可匹配的 token/墙钟预算或独立重复；本次未找到作者公开实现。文中描述 64×64 观察和帧处理，但不足以断言具体发送给 Claude 的图像/文本封装。

**本项目推论：** 增量应是“反例导致旧假设失效，随后修订相应程序并改变行动”。仅加 `rulebook` 文件或更多摘要，不等于复现机制。源码虽实现了 `World model`、`Goal model` 等替换式记忆段，**当前Franzen正式基线配置却是 `ARC3_MEMORY_SECTIONS='off'`，在线没有启用这些段**：[配置](../../notebooks/dfranzen__arc-agi-3-milestone-2-solution.py:10236)、[关闭语义](../../runtime-bundle/src/ARC3-Inference/inference/agent/tool_agent.py:1490)、[关闭时不回传记忆段](../../runtime-bundle/src/ARC3-Inference/inference/agent/tool_agent.py:3930)。离线分析可借这些字段分类；在线重新启用会改变提示与记忆，是必须单独验证的干预，不能当作现成能力。Memento 的三游戏消融主要测到收敛代价，尚未证明能提高本项目最需要的未完成关覆盖。

### PRO-LONG：应更新引用到 v3；记忆价值与持久变量价值仍须分开

[版本历史](https://arxiv.org/abs/2607.20064)显示 v3 于 2026-10-12 发布；[v3 §2–3、Appendix A/B](https://arxiv.org/html/2607.20064v3)扩展 NetHack 跨 episode 和 Kimi/minimal harness 证据，ARC 核心结果仍相同。默认 25 public、500 动作/game、每轮≤20，文本格；GPT 五次、Claude 两次重复。程序访问阶梯 23.1→27.2→38.3→41.2；清空 workspace 为 40.7。Fable 5 的 94.6 pass@1/97.4 best@2 使用 2,000 动作，后者含选择性重跑。64K context 的 44.3 与默认 41.2 在区间内；输入下降没有同比降低 billed 成本。该计量按 API 价格加权，不是本地生成 tokens 或 GPU 时间。

**本项目推论：** 从既有历史按程序提取证据，比要求模型主动维护额外数据 API 更值得优先排查。但 Franzen 已有 Python history，不应再造同一功能。候选需要指出原来不可获取、被截断或无法正确消费的具体信息。v3 没有提供 Qwen3.8-Flash-Next 或单 GPU 的收益。作者仓库主入口已是通用 CLI 集成，ARC 复现内容在 [research/arc-agi-3](https://github.com/alexisfox7/PRO-LONG/tree/main/research/arc-agi-3)。

### 最新官方跨模型证据：Argon 支持连续推理的重要性，但不是干净消融

[ARC Prize 的 Gemini 4 Argon 官方页](https://arcprize.org/results/google-gemini-4-argon)在本次访问给出半私有 55 游戏 low reasoning：Standard 49.8，Provider Adapter 97.5；Adapter 保留 opaque reasoning state 并压缩长会话。然而 Standard low 仅 42/55 运行完成，medium 46/55、high 19/55，均受 API 问题影响，评分保留未完成的部分得分。不能把 47.7 点差全归因于记忆，更不能把官方 API adapter 视为离线可用方案。

**本项目推论：** 应审计自己是否在 handover、上下文裁剪、工具回传时丢弃原本有价值的信息；这比增加一套外部摘要更接近可迁移原因。只把透明日志中可观察的丢失当候选，不尝试猜测或复制闭源 opaque state。

## 结合本项目负结果后的五项选择

以下是研究者提出的迁移假设，尚无本项目提分证据。这里的优先级只比较前沿机制；它不高于更便宜、无需模型学习新接口的现有调度单开关。实现前应结合013本地轨迹审计选择**一个**，不要把五项合并。

### 1. 首选：修复模型自然计算的接续点，替代另学一种保存协议

012证明 `put/get` 合同存在，但没出现读取；这不支持继续扩大API。应先在原始请求中找三类具体位置：模型下一段引用上一段变量而触发错误；重复生成同一组解析/搜索中间结果；函数虽然保留却因隐式常量变错。只有其开销/失败覆盖足够大，才为那一类设计最窄的连续性支持。

可以比较两种不同假设，不能同时修改：A. 用模型已经自然采用的显式参数函数接续计算；B. 在动作未改变观察时保留计算对象，并让失效边界直接可见。B需要证明新状态不会误用旧解，不能承诺透明保存所有 globals。007 已试过保留函数并退分，所以“保住更多代码”本身不再构成新假设。

采用证据应是**同一次真实游戏中的前段计算被后段直接消费，减少重算或避免一个实际错误**；人工编写 `get` 测试、给模型硬塞调用前缀、接口次数上升都不算。此候选主要解决执行连续性；原始观察证据与自写假设仍须区别。

### 2. 有条件优先：把局部搜索变成可恢复、可反证的计算结果

先从模型本来就写 BFS、枚举、路径规划的轨迹入手，测多少失败来自重复搜索、搜索结果被截断、timeout 后重来或计划不能执行。若占比足够高，保存的是搜索工作与当前适用状态，而不是新的世界模型模板。CPU搜索必须有时限/节点限额，恢复后检查观察版本，返回短计划前缀与已检验的预测；失配立即交回 actor。

这条路线试图提高**单位GPU时间的有效规划量**。机制成功需要看到模型自己的搜索产物被执行，并减少下一次生成；最终仍要同墙钟比较全池覆盖。不要以搜索节点数、模型验证率、已解关动作减少代替得分。局部状态可以显式携带历史，不强迫每次从末帧重新构造完整世界。

### 3. 次选：让已有规则与目标被真实反例撤回

003未触发目标反证，012成功保存的又是尚未确认的解，说明“声明事实”和“验证事实”混淆仍值得查。先在**离线轨迹分析**中按 `World model/Goal model/Open questions` 的含义标注自然出现的目标候选病例：它给出可达到的预期状态，实际抵达却未过关，观察下一段是否撤回或降低该假设，并改用另一个解释。这不是恢复在线记忆段。若之后研究在线机制，必须把从 `off` 重新启用、增加证据引用或改变提示分别作为独立候选；不能与新工具叠加，也不能忽略原版选择关闭记忆段的负结果历史。避免每步大表格与强制新LLM回合。

Memento式语义版本链可以用于**离线分析**：记录原假设、反例action、修订后假设、对应程序差异、后续动作变化。只有模型自己实际改正才算采用，程序只是保存了文本不算。这比先写一个全局rulebook框架更便于在小预算证伪。

### 4. 保留为专门实验：上下文与检索成本的联合设计

010/011说明信息可访问并不充分；增加检索调用也可能挤占其他游戏推理。先测现有活跃上下文中固定说明、重复帧、重复历史、被截断stdout、旧错误结论各占多少，和prefill/cache命中是否受影响。只有证据显示一种冗余消耗了可用历史，才删减这一种冗余，保持信息仍可恢复。

不能简单移植 PRO-LONG 的64K或 VISTA 的100K：模型、缓存与模态不同。更大的上下文也不是无代价。新接口说明若占掉旧交互历史，需要把该损失算进候选成本。此方向可以比再造动画查询更便宜，但它不是纯CPU模拟能够证明的提分，应测真实请求与吞吐。

### 5. 本赛末期不作为主线：完整 Memento/Twin、多世界模型人口、从零训练

完整逐像素世界模型会增加很多编写、回放、修订和LLM验证；目前我们的未完成关还没有证明必须依赖这些步骤。Memento的population只有单游戏动作节省，没有等算力覆盖提升，故不启动全局多代理。大模型教师蒸馏、LoRA/在线训练也缺符合本项目模型、预算、隐藏泛化的直接证据。可以保留为长期研究，不能消耗本轮主要试验配额去追公开100分。

同理，不把公开游戏解答/作者生成的特定关卡程序塞进隐藏求解器。若借鉴第三方代码，必须单独核对代码与模型许可、外部数据截止及实际比赛允许的运行方式；论文“开源”或一个比赛获奖经历不能替代许可判断。

## 把下一轮实验做得更有信息量

1. **候选形成**：本地轨迹审计固定至少三处同类机会，再选最小改变。未找到足够机会时不实现；没有把“更多内存”当默认答案。
2. **采用筛选**：保持基线和候选的短试验都真实运行，用同样的截断/时间安排；观察多个自然病例中是否完成预期链。选择游戏是机制筛选，不能标成未见留出。不要把带答案的人工恢复状态当正式泛化评测。
3. **效果筛选**：采用成立后再做冻结游戏池、等墙钟、两臂独立进程；记录各游戏生成/输入/缓存、CPU计算、真实动作、关卡及总分。总生成量接近不代表每个游戏分配接近。
4. **确认**：保留所有结果并交换运行顺序。不能在第一轮中挑胜局重跑后报告新的平均；多数改进只出现在一个已知游戏时不晋升。
5. **比赛验证**：最后才用完整25公开与允许的正式提交判断外部迁移。公开成绩、Kaggle public、final private仍分别列示，不能据论文估算金牌概率。

若本轮高分Notebook调查发现了更强且可部署的公开实现，先衡量升级基线的机会成本。前沿论文机制不应阻止采用竞赛中已验证的工程改进；也不能在未知许可时把技术得分当奖金资格。

本轮团队交叉审阅后的近期顺序与上述证据一致：**先准备 tail 的25游戏匹配A/B；原生短期普通值交接只做最多1小时的采用筛选；可撤回假设→程序→真实反例留作中期候选。** tail 不是论文已证明的提分方案，它的优势是机制单一、现有实现可审计、不会重复012的新API采用问题；pace 应另开一轮，不能与tail叠加。

Notebook审计提出的 `check_sim`/逐步预测反馈，也只宜拆成局部可选能力。预测须在真实动作前保存，再与随后公开反馈比较；先看后帧再补写预测没有证据价值。状态对象、搜索深度与适用范围由模型明确提供，不把默认颜色当通用角色语义，也不传入未生效的预算参数。出现失配时允许actor放弃模型继续探索，避免将全历史精确复验变成所有动作的前置条件。
